# 01. 개요와 요구사항

근거 자료: 팀 기획 노트(2026-11-14 사진), CP1 보고서(2026-11-03), 배포 목표(많은 사람이 설치해 써 보게 한다).

## 1. 대상 앱

플래닝펫은 일정 관리와 반려동물 키우기를 합친 Java Swing 데스크톱 앱이다.
사용자가 할 일을 해내면 포인트와 경험치를 얻고, 그것으로 고양이를 키우고 방을 꾸민다.

## 2. 특징과 기존 앱 비교

| 앱 | 하는 일 | 플래닝펫과 다른 점 |
|---|---|---|
| Google 캘린더 | 일정 기록과 알림 | 해낸 일에 대한 보상이 없다 |
| Habitica | 할 일을 RPG 퀘스트로 바꾼다 | 전투와 파티 중심이라 익힐 것이 많다 |
| Forest | 집중하는 동안 나무가 자란다 | 일정 관리 기능이 없다 |
| Finch | 자기관리 목표를 하면 펫이 자란다 | 모바일 앱이고 날짜와 시간이 있는 일정 관리가 중심이 아니다 |

플래닝펫만의 특징:

- **아침 브리핑**: 컴퓨터를 켜면 펫이 오늘 할 일을 알려 준다.
- **일정과 성장의 연결**: 할 일을 체크하면 성취도 막대 위를 고양이가 걸어가고 레벨이 오른다.
- **데스크톱, 오프라인**: 공부하고 과제하는 노트북에서 계정 없이 바로 쓴다.

## 3. 이해관계자

| 이해관계자 | 원하는 것 |
|---|---|
| 사용자 (20대 대학생, 취준생) | 해야 할 일을 놓치지 않고, 해낸 만큼 보상받고 싶다 |
| 배포로 만날 일반 사용자 | 설치가 쉽고, 업데이트해도 데이터가 남아 있기를 바란다 |
| 팀 (3명) | 역할(Model, View, Controller)대로 나눠 만들 수 있고 학기 안에 끝나는 범위 |
| 교수 | 수업 내용(요구사항, 유스케이스, UML, Swing MVC)을 적용한 설계 |

## 4. 사용 장면

- **S-1 아침**: 수업 전에 노트북을 켠다. 플래닝펫이 뜨고 고양이가 오늘 할 일과 마감이 가까운 과제를 알려 준다. 출석 보상 +20P를 받고 연속 접속 일수가 하나 오른다.
- **S-2 낮**: 과제 마감 전에 알림이 온다. 과제를 내고 체크하면 포인트를 받고, 고양이가 성취도 막대 위를 한 칸 걷는다.
- **S-3 저녁**: 일정관리 화면에서 내일 할 일을 넣는다.
- **S-4 주말**: 모은 포인트로 상점에서 쿠션을 사서 방에 놓는다. 통계 화면에서 이번 주에 해낸 일을 본다.

S-1의 브리핑과 S-2의 막대는 노트에 있다. 장면 사이의 순서와 세부(마감 전 알림, 주말 통계 등)는 노트를 이어 붙여 만든 것이다.

## 6. 미정

기획 노트와 CP1만으로는 정할 수 없거나, 서로 맞지 않는 것들이다. 정해진 것은 [decisions.md](decisions.md)로 옮긴다.

- **Q-01 URL 파싱 (검토 중).** 목적부터 정해야 한다. 사용자가 어떤 상황에서 URL을 넣는지(과제 공지, 채용 공고, 공모전 등), 그 목적에 URL 파싱이 가장 나은 방법인지 다른 방법(글 붙여넣기, 파일 가져오기, 캘린더 구독 등)과 비교한다. 그 뒤에 읽는 방식(페이지 구조 읽기, LLM)과 API 키 관리를 정한다. 학교 LMS처럼 로그인해야 보이는 페이지는 주소만으로 읽을 수 없다는 점도 비교에 넣는다.
- **Q-03 성취도 막대가 세는 것.** 후보는 경험치와 하루 달성도다. 게임 요소 담당 팀원이 정한다(D-04). 경험치로 정하면 pet 화면의 LV와 같은 것을 두 번 보여 주게 되는지 함께 본다. CP1에는 경험치와 성장 규칙이 Model 담당으로 적혀 있어서, 담당이 바뀐다면 CP1과 달라진 점으로 남겨야 한다.
- **Q-04 일정 항목.** 걸리는 시간(D-06)과 시작 시각(D-10) 말고 마감, 분류, 반복, 우선순위 중 무엇을 넣을지. 프로토타입 README에는 참고 이미지에 시간, 분류, 반복 설정이 있었다고 적혀 있다.
- **Q-05 포인트와 경험치.** 노트에는 포인트(P)만 있고 CP1에는 둘 다 있다. 각각 어디에 쓰는지, 할 일 하나에 얼마를 주는지. 게임 요소 담당 팀원 몫이다.
- **Q-06 연속 접속이 끊기면.** 0으로 돌아가는지, 연속 일수에 따른 추가 보상이 있는지. 게임 요소 담당 팀원 몫이다.
- **Q-08 하루 보상 상한.** 만들자마자 완료해도 보상을 준다(D-02). 모든 할 일에 걸리는 시간이 있으므로(D-06) "하루에 완료한 할 일의 시간 합은 하루를 넘을 수 없다" 같은 규칙으로 하루 범위를 지킬 수 있다. 정확한 규칙은 게임 요소 담당 팀원과 정한다.
- **Q-09 반려동물 선택.** CP1 ④는 "반려동물 선택"인데 노트에는 고양이만 그려져 있다. CP1의 "다마고치형"이 돌보지 않으면 상태가 나빠지는 것까지 뜻하는지도 노트에 없다.
- **Q-10 아이템 종류와 가격.** 상점에서 팔 아이템과 가격. 상점 위치와 방 안 배치는 D-13에서 정했다.
- **Q-12 설정 항목.** 컴퓨터 켤 때 실행(D-03) 말고 알림 켜기, 데이터 백업 등을 넣을지.
- **Q-13 지원 운영체제.** 설치 파일을 macOS와 Windows 중 어디까지 만들지. 컴퓨터 켤 때 실행(D-03)은 운영체제마다 등록 방법이 달라서 이 결정에 따라 일이 늘어난다.
- **Q-14 대상 범위.** 노트에서 "직장인(이직 준비)"에 줄이 그어져 있다. 대학생(취준생)으로 좁힌 것이 맞는지.
- **Q-15 기존 앱 비교의 근거.** 2절의 비교는 각 앱의 널리 알려진 특징으로 썼고, 최신 기능은 확인하지 않았다.
- **Q-16 자동 배치 (검토 중).** 이미 지나간 시간과 일정은 건드리지 않는다는 것만 정해졌다. 정할 것:
  - 배치 알고리즘
  - 옮기면 안 되는 일정: 수업처럼 시간이 정해진 일정과 옮길 수 있는 할 일을 나눈다(Q-04와 함께 정함)
  - 어느 날까지의 일정을 보고 배치할지. 내년 일정이 있으면 내년까지 봐야 하는지
  - 결과를 바로 저장할지, 사용자가 보고 확정할지
