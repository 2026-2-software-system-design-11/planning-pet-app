# 05 입력 항목과 사람의 예상

05의 입력 항목마다, 명세를 모르는 사람 열 명이 블라인드 검사에서 예상한 동작(누르기, 글 쓰고 Enter, 글 쓰고 가까운 버튼 누르기)을 도구 없는 세션이 묶어 05의 형식과 범위, 오류 처리와 견줬다. 그림 번호와 05 항목의 대응은 `prototype/qa/blind/expect-map.tsv`에 있다. "설계서"는 05를 뜻한다.

| 항목 | 다수 예상(몇 명) | 설계서 | 견줌 | 다른 점 |
|---|---|---|---|---|
| 메인 1. 출석 (01-1 누르기) | 보유 포인트가 100P에서 120P로 오르고, 버튼이 흐려지거나 "출석 완료" 같은 글자로 바뀐다(10명). | 글자 "출석 +20P", 앱 날짜 하루에 한 번. 이미 출석했으면 "출석 완료"로 바뀌고 비활성. | 같음 | 없음. 연속 접속 숫자가 바뀌는지(1명이 물음)는 설계서에 없다. |

| 메인 2. 다음 달 (01-8 누르기) | 달력이 2026년 12월로 바뀐다(10명). | 한 달씩 옮기고 고른 날짜는 그대로. | 같음 | 없음 |

| 메인 8. 삭제 (01-15 누르기) | 그 줄이 목록에서 사라진다(10명). 매주 반복 일정이면 확인 창(screen-11)이 먼저 뜬다(8명). 반복이 아닌 이 할 일에도 확인 창이 뜨는지는 모른다(7명). | 일정 삭제 확인 창을 거친다. 저장에 실패하면 되돌리고 저장 실패 창. | 일부 다름 | 설계서는 반복 여부와 상관없이 늘 확인 창을 거치는데, 다수는 반복 일정일 때만 묻는다고 보거나 몰랐다. |
| 시각 고치기 창 1. 시작 시각 (07-1 누르기) | 시각이 바뀌거나 고칠 수 있다(10명). | 00:00부터 23:55. 기본은 그 일정의 시작 시각, 시각 없는 할 일이면 `defaultStart`. 끝이 24:00을 넘으면 저장하지 않고 "하루 안에 끝나야 해요". | 같음 | 없음. 몇 분씩 바뀌는지(1명이 물음)는 설계서에도 없다. |
