## 4. QA가 화면을 어떻게 읽는가

- 누르는 것: 체크박스, 빠른 추가 칸, 출석 버튼, 화면 바꾸기, 달력 날짜, pet 아이템 버튼은 화면의 부품을 누른다.
- 창 안의 것: 일정 입력 창, 시각 고치기 창, 자동 배치 결과 창, 상점, 삭제 확인 창은 창을 띄우지 않는다. 창의 칸을 채우거나 창의 표를 만든 뒤, 창의 버튼이 부르는 함수를 부른다.
- 읽는 것: 위 막대, 메인 목록, 일정관리 오른쪽 목록, 달력 칸, 레벨, pet 화면, 상점 표, 결과 창 표, 일정관리 펫은 부품의 글자를 읽는다. 메인 말풍선과 성취도는 막대가 그리는 값(`Store.talk`, `checkables`)을 읽고, 시간표는 그린 그림이 아니라 열 계산(`Planner.columns`)과 그날 일정을 읽는다. 그래서 그리는 쪽의 결함은 화면 그림(`prototype/snap.sh`)으로 본다.

## 5. 명세 밖에서 찾은 것

위 QA는 기대값을 명세에서 가져오므로 명세가 어색하게 정한 동작은 통과시킨다. 명세를 모르는 세션이 화면만 보고 예상한 동작과 실제를 견준 결과는 [blind/README.md](blind/README.md)에 있다(#75). 명세와 상관없이 화면이 지켜야 할 자동 규칙(입력 보존, Enter와 옆 버튼, 용어, 버튼 자리)의 결과는 `qa.sh`가 [rules.md](rules.md)에 쓴다(#79).
