# 02. 유스케이스

요구사항([01-requirements.md](01-requirements.md))을 이루는 유스케이스다. 형식은 수업 슬라이드 "1. Requirements and Changes"의 Parts of a use case(이름, 설명, 액터, 기본 흐름, 대안 흐름, 사전조건, 사후조건)를 따른다. 사후조건은 성공했을 때만 쓴다.

## 액터

|---|---|---|

## UC-01 앱 시작하기

- **설명**: 그날 처음 창을 열면 펫이 오늘 할 일을 알려 준다. 공부를 시작할 때 무엇을 해야 하는지 바로 안다(D-14).
- **액터**: 시작 사용자 또는 운영체제(컴퓨터 켤 때 실행이 켜져 있을 때)
- **사전조건**: 없음
- **기본 흐름**:
  1. 사용자가 앱을 실행하거나, 운영체제가 컴퓨터를 켤 때 앱을 실행한다.
  2. 앱이 저장된 데이터를 읽는다.
  3. 앱이 연속 접속 일수를 갱신한다.
  4. 앱이 메인 화면을 띄운다. 달력은 오늘 날짜를, 할 일 목록은 오늘 할 일을 보여 준다.
  5. 펫이 말풍선으로 오늘 할 일 수와 마감이 가까운 할 일을 알려 준다.
- **대안 흐름**:
  - 2a. 저장된 데이터가 없다(첫 실행): UC-17 반려동물 고르기를 먼저 하고 4로 간다.
  - 2b. 데이터 파일을 읽을 수 없다: 앱은 파일을 덮어쓰지 않고, 원인을 알리는 창을 띄운 뒤 끝낸다.
  - 1a. 앱이 이미 백그라운드에서 실행 중이다: 새로 실행하지 않고 실행 중인 앱의 창을 앞으로 가져온다. 오늘 이 창을 처음 연 것이면 3부터, 아니면 4부터 한다.
  - 2c. 마지막으로 연 지 일주일이 넘었다: 펫이 반겨 주는 말로 5를 대신한다. 지난 할 일이나 끊긴 연속 접속을 탓하지 않는다.
  - 5a. 오늘 할 일이 없다: 펫이 할 일을 추가해 보라고 말한다.
  - 5b. 오늘 이미 브리핑했다: 펫은 브리핑을 되풀이하지 않고 평소 말을 한다.
- **사후조건**: 메인 화면에 오늘 할 일이 보이고, 연속 접속 일수가 오늘까지 반영되어 있다.
- **미정**: Q-06 연속 접속이 끊기면, Q-23 하루가 바뀌는 시각

## UC-02 출석하기

- **설명**: 하루에 한 번 출석하고 포인트를 받는다.
- **액터**: 시작 사용자
- **사전조건**: 메인 화면이 떠 있다.
- **기본 흐름**:
  1. 사용자가 메인 화면 위쪽의 출석 버튼을 누른다.
  2. 앱이 20P를 더하고 오늘 출석한 것으로 기록한다.
  3. 앱이 데이터를 저장한다.
  4. 출석 버튼이 "출석 완료"로 바뀌고 보유 포인트가 갱신된다.
- **대안 흐름**:
  - 1a. 오늘 이미 출석했다: 버튼이 비활성이라 누를 수 없다.
  - 3a. 저장에 실패했다: 포인트와 출석 기록을 되돌리고 저장 실패를 알린다.
- **사후조건**: 오늘 출석이 기록되고 포인트가 20 늘어 있다.
- **미정**: Q-23 하루가 바뀌는 시각

## UC-03 일정 추가하기

- **설명**: 입력 화면에서 일정을 하나 추가한다. 시간, 메모까지 자세히 넣을 때 쓴다.
- **액터**: 시작 사용자
- **사전조건**: 메인 화면이나 일정관리 화면이 떠 있다.
- **기본 흐름**:
  1. 사용자가 일정 추가 버튼을 누른다.
  2. 앱이 일정 입력 화면을 띄운다. 날짜는 선택된 날짜, 걸리는 시간은 30분으로 미리 채워져 있고 시작 시각은 비어 있다(D-07, D-10).
  3. 사용자가 제목을 쓰고 필요하면 날짜, 시작 시각, 걸리는 시간, 메모를 고친다.
  4. 사용자가 저장을 누른다.
  5. 앱이 입력값을 검사하고 일정을 만든다.
  6. 앱이 데이터를 저장하고 입력 화면을 닫는다.
  7. 달력, 할 일 목록, 시간표에 새 일정이 보인다.
- **대안 흐름**:
  - 5a. 제목이 비어 있거나 걸리는 시간이 0 이하다: 저장하지 않고 해당 칸 옆에 고칠 내용을 보여 준다. 3으로 간다.
  - 4a. 사용자가 취소를 누른다: 아무것도 만들지 않고 입력 화면을 닫는다.
  - 6a. 저장에 실패했다: 만든 일정을 되돌리고 입력 화면에 입력값을 남긴 채 저장 실패를 알린다.
- **사후조건**: 새 일정이 저장되어 있고 화면에 보인다.
- **미정**: Q-04 일정 항목

## UC-04 할 일 빠르게 추가하기

- **설명**: 메인 할 일 목록에서 제목만 넣고 오늘 할 일을 바로 추가한다.
- **액터**: 시작 사용자
- **사전조건**: 메인 화면이 떠 있다.
- **기본 흐름**:
  1. 사용자가 할 일 목록 아래 입력칸에 제목을 쓰고 Enter를 누른다.
  2. 앱이 선택된 날짜, 걸리는 시간 30분으로 할 일을 만든다(D-06).
  3. 앱이 데이터를 저장한다.
  4. 할 일 목록에 새 할 일이 걸리는 시간과 함께 보이고 입력칸이 비워진다.
- **대안 흐름**:
  - 1a. 제목이 비어 있다: 아무것도 만들지 않는다.
  - 3a. 저장에 실패했다: 만든 할 일을 되돌리고 입력칸에 제목을 남긴 채 저장 실패를 알린다.
- **사후조건**: 새 할 일이 30분짜리로 저장되어 있다.
- **미정**: 없음

## UC-05 일정 수정하기

- **설명**: 이미 있는 일정의 제목, 날짜, 걸리는 시간, 메모를 고친다.
- **액터**: 시작 사용자
- **사전조건**: 고칠 일정이 화면에 보인다.
- **기본 흐름**:
  1. 사용자가 일정을 두 번 누르거나 수정 버튼을 누른다.
  2. 앱이 현재 값이 채워진 일정 입력 화면을 띄운다.
  3. 사용자가 값을 고치고 저장을 누른다.
  4. 앱이 입력값을 검사하고 일정을 바꾼다. 완료 여부와 받은 보상은 그대로 둔다.
  5. 앱이 데이터를 저장하고 화면을 갱신한다.
- **대안 흐름**:
  - 4a. 입력값이 잘못되었다: UC-03의 5a와 같다.
  - 5a. 저장에 실패했다: 바꾸기 전 값으로 되돌리고 저장 실패를 알린다.
- **사후조건**: 일정이 고친 값으로 저장되어 있다.
- **미정**: Q-20 완료한 할 일의 날짜나 걸리는 시간을 고칠 때 보상

## UC-06 일정 삭제하기

- **설명**: 필요 없어진 일정을 지운다.
- **액터**: 시작 사용자
- **사전조건**: 지울 일정이 화면에 보인다.
- **기본 흐름**:
  1. 사용자가 일정을 고르고 삭제를 누른다.
  2. 앱이 정말 지울지 묻는다.
  3. 사용자가 확인을 누른다.
  4. 앱이 일정을 지우고 데이터를 저장한다.
  5. 화면에서 일정이 사라진다.
- **대안 흐름**:
  - 3a. 사용자가 취소를 누른다: 아무것도 지우지 않는다.
  - 4a. 저장에 실패했다: 지운 일정을 되돌리고 저장 실패를 알린다.
- **사후조건**: 일정이 데이터에서 지워져 있다.
- **미정**: Q-19 완료한 할 일을 지울 때 보상

## UC-07 할 일 완료하기

- **설명**: 해낸 할 일을 체크하고 보상을 받는다. 펫이 자라는 것을 보며 성취감을 느낀다.
- **액터**: 시작 사용자
- **사전조건**: 완료하지 않은 할 일이 화면에 보인다.
- **기본 흐름**:
  1. 사용자가 할 일의 체크박스를 누른다.
  2. 앱이 할 일을 완료로 바꾼다.
  3. 앱이 포인트와 경험치를 더한다.
  4. 앱이 데이터를 저장한다.
  5. 체크박스가 체크되고, 보유 포인트와 성취도 막대가 갱신되며 고양이가 막대 위를 걸어간다.
- **대안 흐름**:
  - 3a. 오늘 받은 보상이 하루 상한에 닿았다: 완료로는 바꾸되 보상은 주지 않고 그 사실을 알린다.
  - 3b. 경험치가 다음 레벨 기준을 넘었다: 펫의 레벨을 올리고 바뀐 모습과 레벨 업 연출을 보여 준다.
  - 4a. 저장에 실패했다: 완료와 보상을 되돌리고 저장 실패를 알린다.
- **사후조건**: 할 일이 완료로 저장되어 있고, 받은 보상이 그 할 일에 기록되어 있다.
- **미정**: Q-03 성취도 막대, Q-05 보상 양, Q-08 하루 상한, Q-21 지난 날짜와 미래 날짜의 할 일 완료

## UC-08 할 일 완료 취소하기

- **설명**: 잘못 체크한 할 일을 되돌린다. 받은 보상도 되돌린다(D-02).
- **액터**: 시작 사용자
- **사전조건**: 완료한 할 일이 화면에 보인다.
- **기본 흐름**:
  1. 사용자가 체크된 체크박스를 누른다.
  2. 앱이 할 일을 미완료로 바꾼다.
  3. 앱이 그 할 일로 받은 포인트와 경험치를 뺀다.
  4. 앱이 데이터를 저장한다.
  5. 체크가 풀리고 포인트와 성취도 막대가 갱신된다.
- **대안 흐름**:
  - 3a. 빼야 할 포인트가 보유 포인트보다 많다(이미 상점에서 썼다): Q-22에 따라 처리한다.
  - 3b. 경험치가 줄어 레벨 기준 아래로 내려간다: Q-22에 따라 처리한다.
  - 4a. 저장에 실패했다: 바꾸기 전으로 되돌리고 저장 실패를 알린다.
- **사후조건**: 할 일이 미완료로 저장되어 있고, 그 할 일로 받은 보상이 남아 있지 않다.
- **미정**: Q-22 되돌릴 보상이 부족할 때

## UC-09 달력으로 일정 보기

- **설명**: 메인 화면 달력에서 날짜를 골라 그날 일정을 본다.
- **액터**: 시작 사용자
- **사전조건**: 메인 화면이 떠 있다.
- **기본 흐름**:
  1. 사용자가 달력의 날짜를 누른다.
  2. 앱이 할 일 목록을 그 날짜의 할 일로 바꾼다.
  3. 펫 말풍선과 일정 추가의 기본 날짜도 그 날짜를 따른다.
- **대안 흐름**:
  - 1a. 사용자가 이전 달, 다음 달 버튼을 누른다: 달력이 그 달로 바뀐다. 선택된 날짜는 그대로다.
- **사후조건**: 고른 날짜의 할 일이 목록에 보인다.
- **미정**: 없음

## UC-10 시간표로 일정 보기

- **설명**: 일정관리 화면에서 일정을 시간표 형태로 본다. 하루를 어떻게 쓰는지 한눈에 본다.
- **액터**: 시작 사용자
- **사전조건**: 없음
- **기본 흐름**:
  1. 사용자가 내비게이션 바에서 일정관리를 누른다.
  2. 앱이 오늘이 들어 있는 주(월요일부터 일요일까지)의 시간표를 보여 준다(D-11). 일정은 걸리는 시간만큼의 칸을 차지한다.
  3. 사용자가 오늘 버튼이나 이전, 다음 버튼으로 주를 옮긴다.
- **대안 흐름**:
  - 2a. 시작 시각이 없는 할 일이 있다: 시간표 옆 목록에 따로 보여 준다.
- **사후조건**: 고른 기간의 일정이 시간표에 보인다.
- **미정**: 없음

## UC-11 할 일 자동 배치하기 (검토 중)

- **설명**: 시각이 정해지지 않은 할 일을 빈 시간에 배치한다. 무엇을 언제 할지 고민하는 수고를 줄인다.
- **액터**: 시작 사용자
- **사전조건**: 배치할 할 일이 하나 이상 있다.
- **기본 흐름**: 배치 알고리즘과 범위가 정해지지 않아(Q-16) 흐름의 뼈대만 둔다.
  1. 사용자가 일정관리 화면에서 자동 배치를 누른다.
  2. 앱이 옮기면 안 되는 일정과 지나간 시간을 뺀 빈 시간을 구한다.
  3. 앱이 할 일을 빈 시간에 배치한 결과를 보여 준다.
  4. 사용자가 결과를 확인하고 적용한다.
- **대안 흐름**:
  - 3a. 빈 시간이 모자라 배치하지 못한 할 일이 있다: 그 할 일을 따로 보여 준다.
- **사후조건**: 배치된 할 일에 시작 시각이 정해져 저장되어 있다. 지나간 시간의 일정은 바뀌지 않았다.
- **미정**: Q-16 자동 배치

## UC-12 URL에서 일정 가져오기 (검토 중)

- **설명**: 웹 페이지 주소를 넣어 일정 입력칸을 채운다.
- **액터**: 시작 사용자, 보조 웹 페이지
- **사전조건**: 인터넷에 연결되어 있다.
- **기본 흐름**: 목적과 방법을 비교 중이라(Q-01) 흐름의 뼈대만 둔다.
  1. 사용자가 URL을 넣는다.
  2. 앱이 웹 페이지를 읽고 제목, 날짜, 마감을 뽑는다.
  3. 앱이 뽑은 값으로 일정 입력 화면을 채운다. 저장은 하지 않는다.
  4. 이후는 UC-03의 3부터 같다.
- **대안 흐름**:
  - 2a. 페이지를 읽지 못했거나 일정을 찾지 못했다: 이유를 알리고 빈 입력 화면을 띄운다.
- **사후조건**: UC-03과 같다.
- **미정**: Q-01 URL 파싱

## UC-13 마감 알림 받기

- **설명**: 할 일 시각이나 마감이 다가오면 알림을 받는다. 앱 창을 닫아 두어도 받는다.
- **액터**: 시작 시계, 보조 운영체제, 사용자
- **사전조건**: 앱이 실행 중이다(창이 닫혀 백그라운드에 있어도 된다).
- **기본 흐름**:
  1. 할 일의 알림 시각이 된다.
  2. 앱이 운영체제 알림으로 할 일 제목과 남은 시간을 띄운다.
  3. 사용자가 알림을 누른다.
  4. 앱이 메인 화면을 앞으로 가져오고 그 할 일이 있는 날짜를 보여 준다.
- **대안 흐름**:
  - 1a. 할 일이 이미 완료되었다: 알리지 않는다.
  - 3a. 사용자가 알림을 무시한다: 아무것도 하지 않는다.
- **사후조건**: 사용자에게 알림이 한 번 표시되었다.
- **미정**: Q-25 알림 시각(얼마 전에 알릴지)과 알림을 받을 할 일의 조건

## UC-14 펫 방 보기

- **설명**: 펫이 사는 방에서 레벨과 꾸민 아이템을 본다.
- **액터**: 시작 사용자
- **사전조건**: 없음
- **기본 흐름**:
  1. 사용자가 내비게이션 바에서 pet을 누른다.
  2. 앱이 방, 현재 레벨의 펫 모습, 놓아 둔 아이템, 아이템 칸, 상점 버튼을 보여 준다.
- **대안 흐름**: 없음
- **사후조건**: pet 화면이 보인다.
- **미정**: 없음

## UC-15 아이템 사기

- **설명**: 모은 포인트로 방을 꾸밀 아이템을 산다.
- **액터**: 시작 사용자
- **사전조건**: pet 화면이 떠 있다.
- **기본 흐름**:
  1. 사용자가 상점을 연다.
  2. 앱이 아이템 목록과 가격, 이미 산 아이템 표시를 보여 준다.
  3. 사용자가 아이템을 고르고 사기를 누른다.
  4. 앱이 가격만큼 포인트를 빼고 아이템을 보유 목록에 넣는다.
  5. 앱이 데이터를 저장한다.
  6. 보유 포인트가 갱신되고 아이템 칸에 새 아이템이 보인다.
- **대안 흐름**:
  - 3a. 포인트가 모자란다: 사기 버튼이 비활성이고 모자란 포인트를 보여 준다.
  - 3b. 이미 산 아이템이다: 사기 버튼이 비활성이고 "보유 중"을 보여 준다. 놓기와 치우기는 pet 화면에서 한다(UC-16).
  - 5a. 저장에 실패했다: 포인트와 보유 목록을 되돌리고 저장 실패를 알린다.
- **사후조건**: 아이템이 보유 목록에 있고 포인트가 가격만큼 줄어 있다.
- **미정**: Q-10 아이템 종류와 가격

## UC-16 아이템 놓기와 치우기

- **설명**: 산 아이템을 방에 놓거나 치운다.
- **액터**: 시작 사용자
- **사전조건**: pet 화면이 떠 있고 산 아이템이 하나 이상 있다.
- **기본 흐름**:
  1. 사용자가 아이템 칸에서 아이템을 누른다.
  2. 앱이 아이템이 방에 없으면 놓고, 있으면 치운다.
  3. 앱이 데이터를 저장하고 방을 다시 그린다.
- **대안 흐름**:
  - 3a. 저장에 실패했다: 놓기나 치우기를 되돌리고 저장 실패를 알린다.
- **사후조건**: 방에 놓인 아이템 목록이 저장되어 있다.
- **미정**: 없음. 아이템마다 놓이는 자리가 정해져 있다(D-13)

## UC-17 반려동물 고르기

- **설명**: 처음 시작할 때 키울 반려동물을 고른다.
- **액터**: 시작 사용자
- **사전조건**: 저장된 데이터가 없다(UC-01 2a).
- **기본 흐름**:
  1. 앱이 고를 수 있는 반려동물을 보여 준다.
  2. 사용자가 하나를 고르고 이름을 붙인다.
  3. 앱이 레벨 1의 반려동물을 만들고 데이터를 저장한다.
  4. UC-01의 4로 돌아간다.
- **대안 흐름**:
  - 2a. 이름을 비웠다: 기본 이름을 붙인다.

## UC-18 컴퓨터 켤 때 실행 설정하기

- **설명**: 컴퓨터를 켤 때 앱이 같이 실행되게 하거나 끈다(D-03).
- **액터**: 시작 사용자, 보조 운영체제
- **사전조건**: 없음
- **기본 흐름**:
  1. 사용자가 내비게이션 바에서 설정을 누른다.
  2. 사용자가 "컴퓨터 켤 때 실행"을 켠다.
  3. 앱이 운영체제의 시작 프로그램에 자기를 등록한다.
  4. 앱이 설정을 저장한다.
- **대안 흐름**:

  - 3a. 등록에 실패했다(권한, 지원하지 않는 실행 방식): 설정을 켜지 않고 이유를 알린다.
- **사후조건**: 운영체제 시작 프로그램 등록 상태와 설정 화면의 표시가 같다.

## UC-19 창 닫기와 앱 끝내기

- **설명**: 창을 닫아도 앱은 알림을 위해 남아 있고, 끝내고 싶을 때는 따로 끝낸다(D-03).
- **액터**: 시작 사용자
- **사전조건**: 앱이 실행 중이다.
- **기본 흐름**:
  1. 사용자가 창의 닫기 버튼을 누른다.
  2. 앱이 창을 숨기고 트레이(Windows 작업 표시줄 오른쪽, macOS 메뉴 막대)에 아이콘으로 남는다.
  3. 사용자가 트레이 아이콘을 누르면 창이 다시 보인다.
- **대안 흐름**:
  - 1a. 처음으로 창을 닫았다: 앱이 트레이에 남아 있다고 한 번 알려 준다.
  - 3a. 사용자가 트레이 메뉴에서 끝내기를 누른다: 앱이 완전히 끝난다. 이후 알림은 오지 않는다.
- **사후조건**: 창이 숨겨지고 앱은 백그라운드에서 실행 중이다.
- **미정**: Q-27 운영체제가 트레이를 지원하지 않을 때

## 미정

01의 미정에 이어 번호를 붙인다.

- **Q-19 완료한 할 일을 지울 때 보상.** 완료 취소는 보상을 되돌린다(D-02). 지울 때 되돌리지 않으면 "만들고, 체크하고, 지우기"를 되풀이해 보상을 모을 수 있다. 지울 때도 되돌릴지, 하루 상한(Q-08)에 지운 할 일도 셀지 정해야 한다.
- **Q-20 완료한 할 일을 고칠 때 보상.** 완료한 할 일의 걸리는 시간을 늘리거나 날짜를 바꾸면 보상과 하루 상한 계산이 달라질 수 있다. 고치면 보상을 다시 계산할지, 완료한 할 일은 못 고치게 할지 정해야 한다.
- **Q-21 지난 날짜와 미래 날짜의 할 일 완료.** 어제 할 일을 오늘 체크해도 되는지, 다음 주 할 일을 미리 체크해도 되는지. 하루 상한(Q-08)의 "하루"가 할 일의 날짜인지 체크한 날인지도 이것에 달려 있다.
- **Q-22 되돌릴 보상이 부족할 때.** 완료 취소로 포인트를 빼야 하는데 이미 상점에서 써서 모자라면 포인트를 음수로 둘지, 0에서 멈출지, 취소를 막을지. 경험치가 줄어 레벨 기준 아래로 가면 레벨을 내릴지도 정해야 한다.
- **Q-23 하루가 바뀌는 시각.** 자정에 바뀌면 새벽까지 깨어 있는 대학생의 출석과 연속 접속이 어색해진다. 자정으로 할지 새벽(예: 4시)으로 할지 정해야 한다.
- **Q-25 알림 시각과 대상.** 마감 몇 분 전에 알릴지, 사용자가 바꿀 수 있는지, 시작 시각이 없는 할 일도 알릴지.
- **Q-26 반려동물 이름.** 이름을 붙이는 기능이 필요한지. 노트와 CP1에 없다. 펫이 말을 거는 앱이라 이름이 있으면 자연스럽지만 범위가 늘어난다.
- **Q-27 트레이를 지원하지 않는 환경.** Java의 트레이 기능은 운영체제에 따라 지원하지 않을 수 있다. 그때는 창을 닫으면 앱을 끝낼지 정해야 한다.
