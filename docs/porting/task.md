# 단위 M2a. 일정 값

[본 구현으로 옮기기](../porting.md) 1절 표의 단위 M2a다. 07의 `Task`와 값 목록 `Kind`, `Category`를 `planningpet.schedule.model`에, `PetKind`를 `planningpet.pet.model`에 둔다. 기준은 06 데이터 절의 `Task` 값과 그 절이 정한 규칙(앱 하루의 시각, 세는 날, 못 끝낸 계획, 지난 반복 사본, 보이는 날), 프로토타입 `schedule/model/Task`다. 입력 검사(`TaskDraft.validate`, 06 2번)는 M2b 단위(`docs/porting/task-check.md`)다.

07 안에서 정한 것과 그 까닭:

- **값은 생성자 하나로 모두 받는다.** 필드는 private이고 메서드로만 바꾼다(D-109). 저장(M8)은 `task` 표 한 행의 값을 모두 되살려야 하고(07 저장 형식), 일정 넣기(M4)도 입력 하나로 값을 모두 정한다. 그래서 생성자가 06 데이터 표 순서대로 값을 받고, 읽는 메서드(`getTitle` 같은 것, 07 읽는 법)를 둔다. 값을 바꾸는 메서드는 그 일을 옮기는 단위(M4, M6, M9)가 더한다. `repeat`는 `Repeat`이 들어오는 M3에서 생성자에 더한다.
- **처음 값은 `Task`가 아니라 만드는 쪽이 정한다.** 프로토타입은 생성자가 메모 빈 글, 유형 기타, 그 밖은 `null`, 0, false로 채운다. 본 구현은 값을 모두 받으므로 06 데이터 절의 처음 값은 일정 넣기(M4)가 지킨다.
- `Kind`와 `Category`는 07 그림대로 따로 된 enum이다. `Category`는 D-54 순서(학업, 운동, 프로젝트, 개인/취미, 기타)이고 화면 글을 `label()`로 준다. `PetKind`는 07 "프로토타입에서 옮긴 것"대로 view에서 model로 옮긴다.
- 07은 `onTimetable(day)`로 적었지만 프로토타입과 06 데이터 절에서 그 날은 앱의 오늘이라 인자 이름을 `today`로 둔다. 보이는 날 `shownOn(day, today)`은 07이 그리지 않았지만 06 데이터 절의 규칙이라 프로토타입 이름대로 옮긴다. `pastDue(today)`(마감이 지난 기간 할 일)도 같다.

## 1. 화면에서 따라 할 단계

이 단위는 화면이 없다. 값과 규칙이 화면에 드러나는 곳은 아래이고, 화면은 뒤 단위(S3, S4, S5)가 옮긴다.

1. 앱 하루의 시각(D-77): 시계가 11-18 01:30일 때 홈의 "일정 추가"를 눌러 제목을 쓰고 시작 시각 정하기를 켠 뒤 다른 칸은 기본값 그대로 저장하면, 날짜는 앱의 오늘 11-17이고 시작은 다음 날 01:30이다. 그 일은 17일 목록 맨 아래와 일정관리 시간표의 17일 칸 24:00 아래에 놓인다.
2. 기간 할 일(D-65, D-66): 일정 입력 창에서 "E사 지원서"에 기간 안에 하기를 켜 11-16~11-22로 저장하면 그 주 날마다 홈 목록 "기간 안에 할 일"에 "~11/22까지"와 함께 보이고, 끝내면 끝낸 날에만 보인다([UF-2-6](../user-flows.md) 4~11단계).
3. 못 끝낸 계획(D-67): 기간 할 일의 시각을 17일로 정하고 끝내지 않은 채 18일이 되면 17일 시간표에서 빠지고, 18일부터 마감까지 "17일에 하려던 일"이 붙어 보인다(05 메인 목록).
4. 지난 반복 사본(D-69): 매일 반복하는 할 일을 어제 끝내지 않았으면 일정관리 목록에 "지난 날" 없이 흐리게 보인다(05 일정관리 시각 없는 할 일).

프로토타입 결과는 `prototype/src`를 컴파일한 클래스로 `Task`를 부르는 버리는 Java 파일에서 얻었다(develop `3df9d0c`, JDK 21.0.11). 값은 프로토타입의 public 필드에 넣었다. 06 데이터 절에는 검사 줄이 없어 모두 `E-TASK`, `E-CAT` 번호다. 따로 적지 않으면 오늘은 11-18(수)이고, "계획 11-17 10:00, 마감 11-20"은 기간 첫날과 날짜가 11-17이고 시작 시각이 10:00인 기간 할 일이다. `shownOn`은 11-14부터 11-22까지 날마다 넣어 보이는 날을 적었다. 경계마다 본 것:

- E-TASK-4: 시각 없는 일정의 앱 하루 시각은 없다. 부르는 쪽(목록, 시간표)이 `timed()`를 먼저 본다.
- E-TASK-6: 보통 할 일은 끝낸 날과 상관없이 날짜로 센다(06 데이터 절 "세는 날").
- E-TASK-9: 06 데이터 절은 끝내면 `doneDay`가 있다고 적었다. 끝냄은 보상(M9)의 `Task.finish`가 `doneDay`와 함께 적으므로 화면에서는 생기지 않는다. 프로토타입은 끝낸 채로 만든 목 데이터를 위해 날짜로 센다. 그대로 옮긴다.
- E-TASK-28: 정한 날이 마감 날이면 정한 날에서 떠난 적이 없어 마감이 지나도 그 칸에 남는다(06 데이터 절 "못 끝낸 계획"의 마지막 문장). 보이는 날도 마감 날 하나라 같은 날이다.
- E-TASK-27, 36: 마감이 지나면 정한 날의 목록과 시간표로 돌아가지 않고 마감 날에만 시각 없는 일처럼 보인다(06 데이터 절, D-67).
