# 단위 S2l. 데이터 파일을 못 읽음 창

[본 구현으로 옮기기](../porting.md) 1절 표의 단위 S2l이다. 데이터 파일을 읽을 수 없을 때 뜨는 창(02 UC-01 2b)의 내용을 `planningpet.app.view.UnreadableDialog`에 둔다. 기준은 [05 그 밖의 창과 알림](../05-ui-design.md)의 "데이터 파일을 못 읽음" 줄과 그 아래 원인 표, 06 21번(T-STORE-3, T-STORE-4), 07 저장 형식과 [seq-uc01](../diagrams/seq-uc01.puml), 이슈 #431이다. 프로토타입은 목 데이터만 읽어 이 창이 없으므로 비교 기준이 없고 05 글과 아래 경계 줄이 기준이다(porting.md 2절 6번).

이 단위가 옮기지 않는 것: `Main`이 `load`를 부르고, `UNREADABLE`이면 이 창을 띄우고, 확인 뒤 앱을 끝내는 일은 S2의 `Main` 잇기가 한다. 그래서 이 단위가 끝나도 앱을 열어 이 창을 볼 수는 없고, 창 내용을 창 없이 만들어 검사한다.

07 안에서 정한 것과 그 까닭:

- **창을 만드는 곳은 `app.view.UnreadableDialog`다.** 07의 "controller는 창을 모른다"대로 창은 view가 띄운다. `load`를 부르는 곳이 층 밖의 `Main`이라 controller를 거칠 일이 없고, `Main`은 view의 `pane`만 부른다. `app` 도메인에 둔 것은 이 창이 저장(`DataStore`)의 결과를 보이는 앱 전체의 창이기 때문이다.
- **`pane(reason, file)`이 창 내용을 담은 `JOptionPane`을 돌려준다.** 띄우는 일(`createDialog`와 `setVisible`)과 창 내용을 떼어, 창을 띄우지 않고 글과 부품을 검사한다. 파일 자리 `file`은 부르는 쪽이 데이터 폴더의 `planningpet.db`로 넘긴다. 저장의 파일 이름(`SqliteDataStore.FILE`)은 store 층 안의 값이라 view가 알지 않는다.
- **원인 글과 다음에 할 일은 `UnreadableDialog`가 갖는다.** 이 창만 쓰는 고정된 표이고 규칙이 없다. 버린 안: `LoadResult.Reason`에 화면 글을 두기. 저장 코드가 쓰지 않는 화면 글이 저장의 결과 값에 붙는다. 원인마다 글을 `switch`로 고르므로 원인이 늘면 글을 넣기 전에는 빌드되지 않는다.
- **버튼은 "확인" 하나다.** 기본 `JOptionPane`의 버튼 글은 로캘을 따라 "OK"가 될 수 있어 글을 정해 넣는다.

## 1. 화면에서 따라 할 단계

`Main` 잇기(S2) 뒤에 앱을 열어 따라 할 수 있다.

1. 데이터 폴더에 다른 프로그램의 파일을 `planningpet.db` 이름으로 두고 앱을 연다. 제목 "데이터를 읽지 못했어요"인 오류 창에 "플래닝펫 데이터 파일이 아니에요", "파일은 지우지 않고 그대로 두었어요", "원래 planningpet.db를 이 자리에 다시 두세요"와 그 파일의 자리가 보인다(UC-01 2b, T-STORE-3).
2. 새 버전 앱으로 쓴 `planningpet.db`를 옛 앱으로 연다. 원인 글이 "새 버전의 플래닝펫에서 만든 파일이에요", 다음에 할 일이 "이 컴퓨터의 플래닝펫을 최신 버전으로 업데이트해 주세요"다(T-STORE-4).
3. 파일 자리 칸의 글을 골라 복사한다. 칸의 글은 고칠 수 없다.
4. 확인을 누르면 창이 닫힌다. 파일은 바뀌지 않는다.

## 2. 입력의 경계와 결과

프로토타입 결과는 모두 "없음"이다(이 창이 없다). 06에 검사 줄이 없는 경계는 `E-UNREAD` 번호다. 따로 적지 않으면 파일 자리는 `/Users/나비/Library/Application Support/PlanningPet/planningpet.db`다. "본 구현" 칸의 결과는 `UnreadableDialogTest`가 번호 이름의 테스트로 확인한다.

| 번호 | 입력과 경계 | 넣은 값 | 프로토타입 결과 | 본 구현 |
|---|---|---|---|---|
| T-STORE-4 | 앱보다 높은 형식 번호(창 글) | `NEWER_VERSION` | 없음 | 원인 글 "새 버전의 플래닝펫에서 만든 파일이에요", 다음에 할 일 "이 컴퓨터의 플래닝펫을 최신 버전으로 업데이트해 주세요" |
| E-UNREAD-1 | 플래닝펫 데이터 파일이 아님(T-STORE-3의 창 글) | `NOT_DATA_FILE` | 없음 | "플래닝펫 데이터 파일이 아니에요", "원래 planningpet.db를 이 자리에 다시 두세요" |
| E-UNREAD-2 | 옛 형식을 옮기다 실패 | `UPGRADE_FAILED` | 없음 | "옛 형식 파일을 새 형식으로 바꾸지 못했어요", "앱을 다시 켜 보거나 최신 버전을 다시 받아 주세요" |
| E-UNREAD-3 | 읽다 오류 | `READ_ERROR` | 없음 | "파일을 읽다 오류가 났어요", "백업해 둔 파일이 있으면 이 자리에 넣어 주세요" |
