# 단위 S2e. 고르기 창 그림 도구

[본 구현으로 옮기기](../porting.md) 1절 표의 단위 S2e다. 07 "고르기 창, 데려오기 창, 로고의 부품"대로 하늘 언덕 바탕, 리본, 카드 안 덤불과 데이지를 그리는 `PickScene`을 `planningpet.pet.view`에 둔다. 06에 이 그림의 검사 줄은 없고, 기준은 [05 화면 설계](../05-ui-design.md) "반려동물 고르기 창", D-113, [디자인 시스템](../design-system.md) 10절 "반려동물 고르기 창", 프로토타입 `pet/view/PickScene`이다.

반려동물 고르기 창(S2)의 화면은 프로토타입 코드만 860줄이고 테스트를 더하면 PR 한도의 세 배가 넘어 넷으로 나눴다. 이 기록은 #416의 몫(`PickScene`)부터 적고, 뒤 이슈가 자기 몫의 단계와 경계를 이 파일에 더한다. 프로토타입이 가진 것 가운데 #416이 빼는 것과 그것을 더할 이슈:

| 프로토타입 | 옮긴 것 | 더할 이슈 |
|---|---|---|
| `PickScene`(바탕, 구름, 덤불, 데이지, 꽃봉오리, 별, 리본, 하늘 발자국, 색 섞기) | #416이 옮겼다(2절) | 없음 |
| 둥근 입력칸 `RoundField`, 아이콘 `PENCIL`, `CHECK`, `SPARK`, 흐린 안내와 글자 막기(`Ui.hint`, `Ui.limit`), 이름을 코드 포인트로 세기(06 읽는 법) | 없음 | #417 |
| 동물 카드 `PickCard`와 고른 카드의 강조선 자리 `PetArt.heightRatio` | 없음 | #418 |
| 고르기 창 내용 `PickDialog`(로고, 리본 제목, 부제, 카드 줄, 이름 줄 카드, 안내, 버튼 줄, 바탕 패널) | 없음 | #419 |
| 창 만들기(`ask`의 `JDialog`, Enter를 바로 시작에 거는 기본 버튼, 닫기), 버튼을 누르면 펫을 만드는 `apply` | 없음 | `Main` 잇기와 `PetController.adopt`의 이슈(porting.md 1절 표 S2) |

07 안에서 정한 것과 그 까닭:

- **`PickScene`은 프로토타입처럼 패키지 안의 정적 그림 도구다.** 07은 view 클래스의 이름만 그렸고, 부르는 쪽(`PickCard`, `PickDialog`)이 같은 패키지에 있다.
- **바탕은 구름 그림을 받는 `backdrop(g, w, h, cloudImage)`를 패키지 안에 연다.** 그림 파일이 없을 때(구름을 도형으로 그림)를 검사하려는 것이고, [icons.md](icons.md)의 `Backdrop`이 그림을 받는 생성자를 연 것과 같다. 프로토타입 꼴 `backdrop(g, w, h)`는 `Images.CLOUD`로 그것을 부른다. 같은 까닭으로 구름(`cloud`)과 꽃봉오리(`bud`)도 패키지 안에 연다.
- **바탕의 모서리 꽃밭과 별은 `corners`로 뗀다.** 프로토타입은 `backdrop` 안에 둔 반복문이다. 커밋 한도(100줄) 안에서 바탕과 그 검사를 나눠 옮기려고 뗐고, 같은 줄을 같은 차례로 부르므로 그림은 같다.

## 1. 화면에서 따라 할 단계

`PickScene`은 그림 도구라 화면에 보이는 것은 고르기 창(#418, #419)부터다. 그때 보이는 곳은 아래다(디자인 시스템 10절).

1. 빈 데이터 폴더로 앱을 처음 열면 뜨는 반려동물 고르기 창의 바탕은 위가 옅은 하늘색이고 아래로 더 옅어진다. 하늘에 구름 일곱이 떠 있고, 그 아래 양옆이 높고 가운데가 낮은 먼 산, 양옆에서 올라오는 연두 언덕, 가운데가 얇고 양 아래 모서리가 두꺼운 풀 띠가 있다.
2. 창의 양 아래 모서리에 풀 덤불 셋, 흰 데이지 일곱, 노란 꽃봉오리 넷이 있고 바깥 모서리 쪽이 크다. 양옆 언덕 위에 흰 네 갈래 반짝이 별이 하나씩 있다. 창을 키우면 모두 창 높이에 맞춰 커진다.
3. 창 위쪽 리본 제목 "함께할 반려동물을 골라 주세요"는 위로 살짝 굽은 청록 띠이고, 양 끝에서 옅은 청록 꼬리가 뒤로 접혀 V자로 파였다. 띠 양옆 하늘에 기울어진 하늘색 발자국이 하나씩 있다.
4. 동물 카드 안에는 언덕 뒤로 덤불 둘과 데이지 둘이 있다.

## 2. 입력의 경계와 프로토타입 결과

프로토타입 결과는 `prototype/src`를 컴파일한 클래스(develop `bd12dd0`, 프로토타입의 마지막 변경 `2ac06b6`, JDK 21.0.11, macOS)를 부르는 버리는 Java 파일에서 얻었다. `java.awt.headless=true`로, 정한 크기(0과 1은 4x4)의 투명한 `BufferedImage`에 그렸다. 클래스 경로에 `prototype/`(그 아래 `assets/`)를 두었고, 구름 그림이 없을 때는 `prototype/`를 빼고 돌렸다. `bud`와 `cloud`는 프로토타입에서 `private`이라 리플렉션으로 불렀다. 모서리 꽃밭(E-PICK-6)은 프로토타입에 따로 부를 함수가 없어 `backdrop`의 반복문과 같은 인자로 프로토타입 `bush`, `daisy`, `bud`, `star`를 불러 그렸고, 바탕 전체(E-PICK-7~10)는 프로토타입 `backdrop`으로 그렸다. 모두 글이 없는 그림이다. "본 구현" 칸의 "픽셀 같음"은 본 구현을 같은 방법으로 그려 두 그림의 픽셀이 모두 같다는 뜻이다. 결과는 `PickSceneTest`가 번호 이름의 테스트로 확인한다.
