# 단위 M15. 상점과 방

[본 구현으로 옮기기](../porting.md) 1절 표의 단위 M15다. 07의 `Shop`, `Item`을 `planningpet.shop.model`에, `Room`을 `planningpet.pet.model`에 둔다. 기준은 06 20번과 그 검사 줄, 06 22번 T-SAVE-2([store.md](store.md)가 이 단위로 넘겼다), D-19, D-28, D-52, D-53, D-85, 프로토타입 `shop/model/Shop`의 `buy`, `sell`, `satisfaction`, `find`와 `pet/controller/PetController.toggle`이다. 상점 칸, 미리보기 칸, 구매 확인 창, 머리의 만족도와 배치 아이템 카드, `ShopController`는 1절 표대로 S7 나의 방이 옮긴다.

07 안에서 정한 것과 그 까닭:

- **`Item`은 record `Item(ItemId id, int price, String category)`다.** 07은 필드 없이 그렸다. 프로토타입 `Shop.Item`은 이름, 가격, 분류였고, 본 구현은 M7의 `ItemId`가 이름(`label()`)을 가지므로 이름 대신 `ItemId`를 둔다. 분류는 06 20번 `find(category, ...)`의 인자가 글이라 "가구", "장식", "장난감", "기타" 글이다. 일정의 유형 `schedule.model.Category`와 다른 값이다.
- **아이템 열세 개는 `Shop` 안의 바뀌지 않는 목록이다.** 07의 `Shop *-- "13" Item`대로다. `ItemId` 순서(가격 순, 같은 가격은 D-52에 적은 순)로 두어 `find`가 따로 줄 세우지 않아도 가격 순이다. 프로토타입은 이름에서 가격으로 가는 표 `ITEMS`와 `CATALOG`를 public으로 열었다. 본 구현은 07에 없는 표를 열지 않고, 아이템 수와 가격 합(T-SHOP-7)은 `find("전체", "", false)`로 센다.
- **`buy`의 출력은 record `BuyResult(Outcome outcome, int lack)`다.** `Outcome`은 `BOUGHT`, `NOT_ENOUGH`, `ALREADY_OWNED`이고 `lack`은 `NOT_ENOUGH`일 때 모자란 포인트, 그 밖은 0이다. 07은 타입으로만 적었다(07 읽는 법). M9의 `RewardResult.Outcome`과 같은 꼴이다. 프로토타입은 0(샀음), 양수(모자란 포인트), -1(이미 있음)인 정수였다.
- **`satisfaction`과 `find`는 07대로 static이 아닌 메서드다.** 프로토타입은 static이었고 `find`가 가진 아이템을 인자로 받았다. 본 구현의 `find`는 `Shop`이 가진 `AppData`의 `ownedItems`를 읽는다.
- **아이템을 넣고 빼는 일은 `AppData`의 `setOwnedItems`, `setPlacedItems`로 한다.** M7이 둔 메서드라 `AppData`를 고치지 않는다. 산 순서대로 담긴다.
- **`Room`은 07대로 `AppData`를 받고 `toggle`만 갖는다.** 프로토타입은 `PetController.toggle`이 `change` 안에서 놓인 목록을 바꿨다. 본 구현은 그 규칙을 model `Room`에 두고, `change`로 감싸는 일은 S7의 `ShopController.toggle`이 한다(07 `ShopController --> Room`).

## 1. 화면에서 따라 할 단계

이 단위는 화면이 없다. 규칙이 화면에 드러나는 곳은 나의 방의 머리 카드, 상점 칸, 미리보기 칸, 구매 확인 창이고 S7이 옮긴다.

1. 120P로 나의 방을 열어 상점 칸 장식 탭에서 액자 카드를 누르고 구매하기, 확인 창 "액자를 120P에 살까요? 남는 포인트 0P"에서 구매하기를 누르면 0P, 액자 카드 "보유 중", 방에 액자, "배치 아이템 3 / 13"이다([UF-1-3](../user-flows.md) 4단계, T-SHOP-1, `buy`).
2. 같은 날 홈에서 체크를 풀고 다시 체크해도 포인트가 산 뒤 그대로다([UF-1-3](../user-flows.md) 5, 6단계, T-SHOP-5, D-19).
3. 40P로 기타 탭의 쿠션 카드를 누르면 구매하기가 흐리고 "10P 모자라요"다([UF-7-4](../user-flows.md) 1단계, T-SHOP-2, `BuyResult.lack`). 장난감 탭은 털실 공, 뼈다귀 순이다([UF-7-4](../user-flows.md) 2단계, T-SHOP-9, `find`).
4. 가진 러그 카드를 누르고 "방에 놓기", 이어서 "방에서 치우기"를 누르면 방에 깔렸다 치워지고 만족도가 16%에서 11%로 돌아간다([UF-1-3](../user-flows.md) 7단계, [UF-9-3](../user-flows.md) 2단계, T-SHOP-6, `Room.toggle`, `satisfaction`).
5. 처음 실행한 앱의 나의 방은 "방 꾸미기 만족도 0%", "배치 아이템 0 / 13"이다([UF-7-1](../user-flows.md) 3단계, T-SHOP-8).
6. 보유한 아이템 탭에서 쿠션 카드를 누르고 "되팔기 +50P"를 누르면 50P를 돌려받고 쿠션이 보유 목록과 방에서 빠진다([UF-9-3](../user-flows.md) 4단계, T-SHOP-11, `sell`).
7. 저장에 실패하면 산 것을 되돌려 포인트와 보유 목록이 사기 전 그대로다(05 나의 방 입력 항목 12, T-SAVE-2).

경계마다 본 것:

- T-SHOP-5: 0P에서 다섯 개를 끝내 50P, 쿠션을 사 0P, 체크를 풀어 -50P, 다시 끝내 0P다. 체크를 풀면 받은 포인트를 빼므로(D-19) 되풀이해도 포인트가 늘지 않는다.
- E-SHOP-4: 가진 아이템은 포인트를 보기 전에 `ALREADY_OWNED`다. 다시 사는 길로 치운 아이템이 방에 돌아오지 않는다. 돌려 놓는 길은 미리보기 칸의 "방에 놓기"다(05 나의 방).
- E-SHOP-6, E-SHOP-7: 모든 가격이 10의 배수이고 합이 2210이라 백분율의 끝자리가 .5가 되는 가격 합이 없다. 반올림 방식에 따라 결과가 갈리지 않는다.
- E-ROOM-1: 화면은 가진 아이템에만 "방에 놓기"를 보이므로(05 나의 방 입력 항목 12) 화면 밖 길이다. 프로토타입은 사지 않은 아이템을 놓인 목록에 넣어 만족도와 배치 아이템 수가 늘었다. 고친 커밋에서 06 20번 "오류"대로 막는다([porting.md](../porting.md) 4절).
