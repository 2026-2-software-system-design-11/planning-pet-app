# 단위 M3. 반복

[본 구현으로 옮기기](../porting.md) 1절 표의 단위 M3다. 07의 반복 방식 `Repeat`를 `planningpet.schedule.model`에 두고, `Task`에 반복 값 `repeat`를, `TaskDraft`에 반복 칸과 그 검사를 더한다. 기준은 06 데이터 절 `repeat`, 06 2번의 반복 칸 검사 줄(T-VAL-11~13, 15, 16, 18), D-64, 프로토타입 `Repeat`, `TaskCheck`다. 반복하는 날마다 사본을 만드는 일은 M4(일정 넣기, 06 3번)다.

07 안에서 정한 것과 그 까닭:

- `Repeat`는 프로토타입처럼 매일인지와 고른 요일들의 record다. 같은 반복의 사본은 같은 값이다(06 데이터 절). 반복하는 날인지(`has`)와 기간 안의 반복하는 날(`dates`)을 옮긴다. 프로토타입의 `toString`("DAILY", "월, 목")은 저장 꼴이라 M8, `text(weekStart)`(한 주 시작부터 잇는 요일 글)은 펫 말과 화면 글이라 M10과 S4가 옮긴다.
- `TaskDraft`에 반복 방식, 반복 끝나는 날, 수정인지(`editing`)를 값으로 더한다. 수정할 때는 반복 칸을 검사하지 않으므로(D-42) `validate()`가 알아야 하고, 07이 `validate()`를 인자 없이 그렸다(M2b와 같은 까닭).
- `Task` 생성자에는 06 데이터 표 순서대로 `seriesId` 뒤에 `repeat`를 더한다.

## 1. 화면에서 따라 할 단계

이 단위는 화면이 없다. 반복 칸이 화면에 드러나는 곳은 아래이고, 화면은 S4 일정 입력 창 단위가 옮긴다.

1. 홈에서 "일정 추가"를 눌러 제목 "채용 공고 확인", 반복 "매일"을 고르면 흐린 끝 날짜가 날짜에 4주를 더한 날이다. 끝 날짜를 날짜보다 앞으로 바꿔 "저장"을 누르면 반복 칸 아래 "반복 끝나는 날이 날짜보다 전이에요"가 보이고 창은 열린 채다([UF-5-4](../user-flows.md) 1단계, 06 T-VAL-12).
2. 반복 사본을 두 번 눌러 "일정 수정" 창을 열면 반복 칸은 그 값인 채 비활성이고, 저장할 때 반복 칸은 검사하지 않는다([UF-5-4](../user-flows.md) 6단계, D-42).

경계마다 본 것:

- E-REP-4: 입력 창의 요일 단추는 요일마다 하나라 같은 요일이 두 번 들어오지 않는다.
- E-REP-9, 10: 사본 수를 세는 검사가 끝 날짜가 아주 먼 반복에서도 120개를 넘는지만 알면 되므로 121개에서 멈춘다.
- E-VAL-21, 22, 28: 수정할 때 반복 칸은 보이기만 하는 칸이라 사용자가 풀 수 없는 오류를 내지 않는다(D-42). 마감 칸은 수정일 때도 검사한다(06 2번).
- E-VAL-25, 26: 반복 칸 오류는 기간, 요일, 끝 날짜, 반복하는 날, 사본 수 순서로 하나만 담는다.
- E-VAL-27: 입력 창은 반복을 고르면 끝 날짜를 늘 채워(06 14번 `repeatEndFor`) 화면에서는 생기지 않는다.
- D-64의 문장 "끝 날짜를 앞당겨 주세요"는 06 2번이 입력 창의 칸 이름("반복 끝나는 날")으로 바꿨고(D-94, D-73), 프로토타입도 06과 같다.
