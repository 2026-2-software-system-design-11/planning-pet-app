# 단위 M9. 보상

[본 구현으로 옮기기](../porting.md) 1절 표의 단위 M9다. 07의 `Rewards`, `Level`, `DailyProgress`를 `planningpet.reward.model`에, `Visits`를 `planningpet.app.model`에 두고 `Task.finish`, `unfinish`를 더한다. 기준은 06 8~13번과 그 검사 줄, D-18, D-19, D-20, D-48, D-55, 프로토타입 `reward/model`의 `Game`, `Level`, `RewardResult`, `DailyProgress`와 `app/model/Visits`다.

PR 하나의 크기 한도(1절) 때문에 셋으로 나눠 옮긴다. 할 일 끝내기의 보상과 레벨(06 8번, 10번, `Task.finish`)은 #359, 체크 풀기와 출석(9번, 11번, `Task.unfinish`)과 앞 단위가 넘긴 T-EDIT-1, T-DEL-1, T-EDIT-49의 포인트와 경험치, T-SAVE-1, T-SAVE-4는 #360, 연속 접속과 오늘 끝낸 일(12번 `Visits`, 13번 `DailyProgress`)과 T-LIST-3, T-LIST-7의 "끝낸 수 / 수"는 #361이다. 체크박스와 출석 단추, 펫 말풍선은 S1, S3과 M10이 옮긴다.

07 안에서 정한 것과 그 까닭:

- **`Level`은 값 넷을 가진 바뀌지 않는 값이다.** 07대로 레벨, 모습 단계, 레벨 안에서 모은 경험치(`inLevel`), 다음 레벨까지의 폭(`span`)을 갖고 `of(exp)`로만 만든다. 레벨 10이면 폭은 0이고 `inLevel`은 1600을 넘은 몫이다(06 10번). 화면 글 "경험치 {inLevel} / {span}"과 "최고 레벨"(`text()`), 막대가 찬 비율(`ratio()`)은 프로토타입 `expText`, `expRatio`를 옮긴 읽는 메서드다(07 읽는 법이 그리지 않는 메서드). 나의 방, 캐릭터 창, 홈 펫 카드가 같은 글을 보이므로 model에 두어 창 없이 검사한다(D-109).
- **`RewardResult`는 06 8번 출력의 값을 담는 record다.** 받은 포인트, 받은 경험치, `REWARDED` 또는 `CAPPED`, 고른 펫의 바뀌기 전과 뒤의 `Level`이고, `levelUp()`과 `stageUp()`이 레벨과 모습 단계가 올랐는지 준다. 07은 타입으로만 적었다(07 읽는 법의 값 묶음). 프로토타입은 받은 포인트와 경험치를 담지 않고 레벨 수만 담았다. 값을 더 담을 뿐 동작은 같다.
- **`Task.finish(day, points, exp, pet)`는 끝냄, 끝낸 날, 받은 보상을 한 번에 적는다.** 받은 포인트와 경험치가 모두 0이면(하루 상한, D-18) `rewardDay`를 적지 않고 `null`로 둔다. 프로토타입 `Game.complete`가 상한일 때 `rewardDay`를 적지 않은 것과 같다(T-RWD-5).
- **`Rewards`는 생성자로 `AppData`를 받고 오늘은 인자로 받는다.** 07대로다. 포인트, 하루 상한 횟수, 고른 펫의 경험치는 M7, M8이 둔 값 넣는 메서드로 바꾼다. 프로토타입 `Game`은 `Store.today()`를 스스로 읽었다.
- **`Task.unfinish()`는 끝냄과 받은 보상을 모두 지운다.** `done`을 false로, 받은 포인트와 경험치를 0으로, `doneDay`, `rewardDay`, `rewardPet`을 `null`로 한다(06 9번). 포인트와 경험치를 빼는 일은 `Rewards.uncomplete`가 일정의 값을 지우기 전에 한다.
- **오늘 횟수는 받은 날과 횟수의 날이 모두 오늘일 때 줄인다.** 06 9번은 "`rewardDay`가 오늘이면"이라고 적었고 프로토타입은 횟수의 날(`rewardCountDay`)도 오늘인지 함께 본다. 오늘 받은 보상이면 그때 횟수의 날이 오늘이 되므로 둘은 같은 결과이고, 프로토타입대로 옮긴다.
- **`Visits`는 생성자로 `AppData`를 받고 오늘은 인자로 받는다.** 07은 `recordOpen(today)`만 그렸고 필드는 그리지 않았다. 연속 접속 일수와 마지막으로 브리핑한 날은 `AppData`의 값이라 `Rewards`처럼 생성자로 받는다(07 "규칙 클래스는 `AppData`를 받는다"). 프로토타입은 `Store`를 받는 static 메서드였다. 06 도메인 표와 07대로 `planningpet.app.model`에 둔다.
- **`DailyProgress`는 끝낸 수와 할 일 수를 가진 바뀌지 않는 값이다.** 07대로 `of(book, today)`로만 만들고, 오늘 `dayPlan`의 `dueToday`, `timed`, `untimed`를 센다. 하나도 없으면 비어 있다(`isEmpty()`). 막대가 찬 비율 `ratio()`는 프로토타입을 옮긴 읽는 메서드이고 비어 있으면 0이다. 글 "{끝낸 수} / {할 일 수}"는 펫 카드를 옮기는 S3이 붙인다.
- **펫이 없을 때의 완료는 닿는 길이 없어 따로 다루지 않는다.** 첫 실행은 펫이 없고(app-data.md E-APP-4) 반려동물 고르기 창이 메인 창보다 먼저 떠서(UC-01 2a) 그동안 체크할 목록이 없다. 06도 이 길을 적지 않았다.

## 2. 입력의 경계와 프로토타입 결과

프로토타입 결과는 `prototype/src`를 컴파일한 클래스로 `Game.complete`, `uncomplete`, `attend`, `Visits.recordOpen`, `DailyProgress.of`, `Level.level`, `stage`, `expText`, `expRatio`, `TaskBook.dayPlan`, `update`, `delete`를 부르는 버리는 Java 파일에서 얻었다(develop `e83b601`, JDK 21.0.11. #362까지 프로토타입은 바뀌지 않았다). 따로 적지 않으면 시계는 11-16 10:00(앱 날짜 11-16), 펫은 고양이 하나(경험치 0)이고 고른 펫이며, 일정은 할 일, 30분, 시각 없음이다. - T-RWD-2, 3: 보상은 할 일의 날짜를 보지 않고 하루 상한은 체크한 앱 날짜로 센다(D-18).
- T-RWD-5: 상한에 걸린 완료도 `doneDay`는 적는다. 성취도(13번)와 통계(29번)가 끝낸 날로 센다(D-66).
- T-RWD-11, 12: 끝내도 날짜, 시작 시각, 첫날, 마감은 그대로이고 `doneDay`만 적는다. 목록은 M5의 보이는 날 규칙(`Task.shownOn`)이 `doneDay`로 고른다(D-66).
- E-LVL-5: 06 10번의 입력은 0 이상이지만, 펫이 하나이던 때의 데이터(`rewardPet` 없음)를 풀면 9번이 고른 펫에서 경험치를 빼므로(D-48) 0보다 작아질 수 있다. 프로토타입은 레벨 1로 보고 그대로 적는다.
- T-UNDO-2: 어제 받은 보상을 풀면 포인트와 경험치는 빠지지만 오늘 횟수는 줄지 않는다. 상한은 받은 앱 날짜의 것이다(D-18, D-19).
- T-UNDO-6, E-UNDO-1: 경험치는 받은 펫에서 뺀다. 받은 펫이 적히지 않은 일(펫이 하나이던 때의 데이터)은 경험치를 받았으면 고른 펫에서 뺀다(06 9번, D-48). 그래서 고른 펫의 경험치가 0보다 작아질 수 있다(E-LVL-5).

- E-VIS-2: 마지막으로 브리핑한 날이 오늘보다 뒤면(컴퓨터 시계를 되돌림) 어제도 오늘도 아니라 06 12번의 "그 밖"이고 1이다.
- E-VIS-3: 연속 접속은 앱 날짜로 센다. 새벽 4시 전에 열면 앞날이다(D-15, 06 1번).

- T-PRG-7, T-LIST-7: 자정 넘은 일은 `date`의 일이라 앱 날짜 11-20의 막대에 든다(D-77).
