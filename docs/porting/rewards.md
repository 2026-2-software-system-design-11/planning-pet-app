# 단위 M9. 보상

[본 구현으로 옮기기](../porting.md) 1절 표의 단위 M9다. 07의 `Rewards`, `Level`, `DailyProgress`를 `planningpet.reward.model`에, `Visits`를 `planningpet.app.model`에 두고 `Task.finish`, `unfinish`를 더한다. 기준은 06 8~13번과 그 검사 줄, D-18, D-19, D-20, D-48, D-55, 프로토타입 `reward/model`의 `Game`, `Level`, `RewardResult`, `DailyProgress`와 `app/model/Visits`다.

PR 하나의 크기 한도(1절) 때문에 셋으로 나눠 옮긴다. 할 일 끝내기의 보상과 레벨(06 8번, 10번, `Task.finish`)은 #359, 체크 풀기와 출석(9번, 11번, `Task.unfinish`)과 앞 단위가 넘긴 T-EDIT-1, T-DEL-1, T-EDIT-49의 포인트와 경험치, T-SAVE-1, T-SAVE-4는 #360, 연속 접속과 오늘 끝낸 일(12번 `Visits`, 13번 `DailyProgress`)과 T-LIST-3, T-LIST-7의 "끝낸 수 / 수"는 #361이다. 체크박스와 출석 단추, 펫 말풍선은 S1, S3과 M10이 옮긴다.

07 안에서 정한 것과 그 까닭:

- **`Level`은 값 넷을 가진 바뀌지 않는 값이다.** 07대로 레벨, 모습 단계, 레벨 안에서 모은 경험치(`inLevel`), 다음 레벨까지의 폭(`span`)을 갖고 `of(exp)`로만 만든다. 레벨 10이면 폭은 0이고 `inLevel`은 1600을 넘은 몫이다(06 10번). 화면 글 "경험치 {inLevel} / {span}"과 "최고 레벨"(`text()`), 막대가 찬 비율(`ratio()`)은 프로토타입 `expText`, `expRatio`를 옮긴 읽는 메서드다(07 읽는 법이 그리지 않는 메서드). 나의 방, 캐릭터 창, 홈 펫 카드가 같은 글을 보이므로 model에 두어 창 없이 검사한다(D-109).
- **`RewardResult`는 06 8번 출력의 값을 담는 record다.** 받은 포인트, 받은 경험치, `REWARDED` 또는 `CAPPED`, 고른 펫의 바뀌기 전과 뒤의 `Level`이고, `levelUp()`과 `stageUp()`이 레벨과 모습 단계가 올랐는지 준다. 07은 타입으로만 적었다(07 읽는 법의 값 묶음). 프로토타입은 받은 포인트와 경험치를 담지 않고 레벨 수만 담았다. 값을 더 담을 뿐 동작은 같다.
- **`Task.finish(day, points, exp, pet)`는 끝냄, 끝낸 날, 받은 보상을 한 번에 적는다.** 받은 포인트와 경험치가 모두 0이면(하루 상한, D-18) `rewardDay`를 적지 않고 `null`로 둔다. 프로토타입 `Game.complete`가 상한일 때 `rewardDay`를 적지 않은 것과 같다(T-RWD-5).
- **`Rewards`는 생성자로 `AppData`를 받고 오늘은 인자로 받는다.** 07대로다. 포인트, 하루 상한 횟수, 고른 펫의 경험치는 M7, M8이 둔 값 넣는 메서드로 바꾼다. 프로토타입 `Game`은 `Store.today()`를 스스로 읽었다.
- **펫이 없을 때의 완료는 닿는 길이 없어 따로 다루지 않는다.** 첫 실행은 펫이 없고(app-data.md E-APP-4) 반려동물 고르기 창이 메인 창보다 먼저 떠서(UC-01 2a) 그동안 체크할 목록이 없다. 06도 이 길을 적지 않았다.

## 1. 화면에서 따라 할 단계

이 단위는 화면이 없다. 보상과 레벨이 화면에 드러나는 곳은 아래이고, 화면은 S3 홈 목록, S7 나의 방, S8 캐릭터 창 단위가 옮긴다.

1. 메인 목록에서 "자소서 초안"의 체크박스를 누르면 위 줄의 보유 포인트가 10 늘고, 펫 카드의 경험치 막대가 10만큼 차며 말풍선이 "잘했어! +10P"가 된다([UF-1-1](../user-flows.md) 2단계, T-RWD-1).
2. 달력 15를 눌러 어제 일을, 달력 17을 눌러 내일 일을 체크해도 같은 10P와 경험치 10을 받고, 하루 상한 횟수는 오늘(11-16)로 센다([UF-2-2](../user-flows.md) 2, 3단계, T-RWD-2, T-RWD-3).
3. 오늘 19번 보상을 받은 뒤 20번째 체크는 10P를 받고, 21번째 체크는 체크만 되고 포인트가 그대로이며 말풍선이 "잘했어! 오늘 보상은 다 받았지만 체크는 계속 돼."다([UF-4-1](../user-flows.md) 2, 3단계, T-RWD-4, T-RWD-5).
4. 고정 일정 "병원 실습"의 체크박스도 할 일과 같이 10P와 경험치 10을 준다([UF-6-1](../user-flows.md) 2단계, T-RWD-7).
5. 경험치 230인 펫으로 체크하면 펫 카드가 "Lv. 4"와 "경험치 0 / 140"이 되고 펫이 한 단계 커진다. 말풍선은 "잘했어! 레벨이 올랐어. 이제 Lv.4, 나 좀 자란 것 같아."다([UF-1-1](../user-flows.md) 7단계, T-RWD-9, T-LVL-4).
6. 나의 방과 캐릭터 창에서 경험치 0인 펫은 "Lv. 1"과 "경험치 0 / 50"이고, 1600을 넘은 펫은 "Lv. 10"과 "최고 레벨"이며 막대가 가득 찼다(05 나의 방 펫 패널, 05 캐릭터 창, T-LVL-1, T-LVL-7).
7. 홈에서 달력 18을 누르고 시각을 정해 둔 기간 할 일 "E사 지원서"(18일 09:00~11:00, 마감 11/22)를 체크하면 10P를 받고, E사 지원서는 끝낸 날의 목록에만 보여 18일 목록과 시간표에서 빠진다. 계획한 18일 09:00은 그대로 남는다([UF-2-6](../user-flows.md) 10단계, T-RWD-11, T-RWD-12).

## 2. 입력의 경계와 프로토타입 결과

프로토타입 결과는 `prototype/src`를 컴파일한 클래스로 `Game.complete`, `Level.level`, `stage`, `expText`, `expRatio`, `TaskBook.dayPlan`을 부르는 버리는 Java 파일에서 얻었다(develop `e83b601`, JDK 21.0.11). 따로 적지 않으면 시계는 11-16 10:00(앱 날짜 11-16), 펫은 고양이 하나(경험치 0)이고 고른 펫이며, 일정은 할 일, 30분, 시각 없음이다. "본 구현" 칸의 결과는 `LevelTest`, `RewardsTest`가 번호 이름의 테스트로 확인한다.
