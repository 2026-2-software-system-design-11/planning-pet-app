# 단위 S1. 창이 보일 때와 날 바뀜

[본 구현으로 옮기기](../porting.md) 1절 표의 단위 S1이다. 07의 `AppController.onWindowShown`과 `DayWatcher`를 `planningpet.app.controller`에, 30초 타이머 `Tray`를 `planningpet.app.view`에, `RewardController.attend`를 `planningpet.reward.controller`에 둔다. 기준은 06 11번, 15번, 23번과 그 검사 줄, 02 UC-01, UC-02, D-21, D-23, 프로토타입 `app/controller/AppController.windowShown`, `DayWatcher`, `reward/controller/RewardController`다.

창 틀은 S1b~S1d, `Main` 잇기(읽기, 못 읽음 창, 첫 실행 갈래, 창과 타이머 잇기)는 S2가 한다(porting.md 1절 "창 틀은 부품 다음이다"). 그래서 이 단위가 끝나도 앱 창은 단위 0의 빈 창이고, 여기 옮긴 것은 S1d와 S2(#434, [main.md](main.md))가 잇는다.

PR 하나의 크기 한도(1절) 때문에 둘로 나눠 옮긴다. 창이 보일 때의 브리핑, 날 바뀜, 30초 타이머는 #389, 출석 controller `RewardController.attend`와 E-ATT-1~4는 #393이다.

02와 07이 다른 점: UC-01 4a는 연속 접속 저장에 실패해도 "5의 브리핑은 그대로 보인다"고 적었고, 07 [seq-uc01](../diagrams/seq-uc01.puml)은 브리핑을 `change`의 edit 안에 그렸다. `change`는 저장에 실패하면 말풍선도 되돌리므로([store.md](store.md), [pet-talk.md](pet-talk.md)) 그림대로면 브리핑이 사라진다. 02 UC-01 4a를 따른다.

07 안에서 정한 것과 그 까닭:

- **`onWindowShown`은 연속 접속을 `change`로 감싸고, 저장에 실패하면 같은 브리핑을 다시 둔다.** 브리핑은 edit 안에서 말해 성공하면 알림이 `change`의 한 번이다. 실패하면 `change`가 연속 접속과 말풍선을 되돌리고 저장 실패 창을 띄운 뒤, 같은 말을 다시 두고 알림을 한 번 더 보낸다(UC-01 4a, E-BRF-5).
- **무엇을 말할지.** `lastOpenDay`가 오늘이면 `USUAL`을 `say(line, 오늘)`로 말해 오늘 목록을 따라간다. 아니면 이전 날이 없으면 `FIRST_RUN`, `ChronoUnit.DAYS.between(이전 날, 오늘)`이 8 이상이면 `WELCOME_BACK`, 그 밖은 `BRIEFING`이다(06 15번, 프로토타입 `Talk.opening`). `BRIEFING`과 `WELCOME_BACK`은 `PetTalk.recount(situation)`을 말풍선이 오늘의 다시 만들 말로 따라가고, `FIRST_RUN`은 수가 없어 따라가지 않는다(pet-talk.md, 프로토타입 `openingRecount`).
- **저장 실패 창의 이름은 "연속 접속"과 "출석"이다.** 06 22번의 예 "할 일 완료"처럼 한 일의 이름을 쓴다.
- **`windowVisible`은 `onWindowShown`이 true로 둔다.** 처음은 false라 창을 아직 띄우지 않은 앱(`--autostart`, 07 실행 모드)은 날이 바뀌어도 말하지 않는다. false로 두는 길(창 닫기의 `onClose`)은 S11이 옮긴다.
- **`DayWatcher`는 만들 때의 앱 날짜를 `lastDay`로 둔다.** `tick(now)`는 `AppDay.of(now)`가 `lastDay`와 다르면 `lastDay`를 바꾸고, 창이 보이면 `onWindowShown`을, 아니면 `AppData.changed()`를 부른다. `onWindowShown`도 알림을 보내므로 어느 쪽이든 날 바뀜 알림은 한 번이다(06 23번 "한 번 알린다", 프로토타입도 한 번). 07 seq-uc01은 `changed()`와 `onWindowShown`을 함께 그렸다. 날짜가 다르기만 하면 알리므로 시계를 되돌려도 알린다(E-DAYW-3, 프로토타입과 같다).
- **고른 날짜 옮기기(T-DAYW-4)는 S3 달력이 한다.** 06 23번은 이것을 날 바뀜 알림에 따른 다시 그리기로 적었고, 07의 `DayWatcher`는 달력을 모른다. S3의 달력이 알림을 받아, 옛 오늘을 고르고 있었으면 새 오늘로 옮긴다.
- **창 숨기기(T-DAYW-3)는 S11이 옮긴다.** 이 단위는 창을 한 번도 보이지 않은 상태로 같은 결과를 검사한다.
- **30초 타이머는 `Tray`에 둔다(07 "30초 타이머는 `app.view.Tray`에 둔다").** 이번에는 `javax.swing.Timer` 30초가 시계의 지금으로 `DayWatcher.tick`만 부른다. 시계는 생성자로 받는다(06 읽는 법). 트레이 아이콘과 메뉴, `dueReminders`는 S11이 같은 클래스에 더하고, 타이머를 켜는 일은 S2의 `Main` 잇기(#434, [main.md](main.md))가 한다.
- **`RewardController`는 생성자로 `AppData`와 `AppController`를 받고 `Rewards`와 `PetTalk`를 만든다.** `attend`는 `change("출석", ...)` 안에서 `Rewards.attend(오늘)`이 true면 `ATTENDED`를 `say(line, null)`로 말한다(수가 없는 말, pet-talk.md). 이미 출석했으면 아무 말도 하지 않는다(프로토타입과 같다. 화면에서는 단추가 흐려 누를 수 없다, 05 메인 입력 항목 1). 저장에 실패하면 지금 `change`대로 포인트, 출석 기록, 말풍선이 되돌아간다(UC-02 3a). `complete`, `uncomplete`는 S3a(#441, [home.md](home.md))가 옮겼다.

## 1. 화면에서 따라 할 단계

이 단위는 화면이 없다. 화면에 드러나는 곳은 화면 머리 오른쪽 카드(S1d)와 홈 펫 카드의 말풍선(S3)이다.

1. 어제 연 앱을 오늘 처음 열면 말풍선이 브리핑하고 화면 머리 오른쪽 카드의 연속 접속이 하나 는다(5일에서 6일). 같은 날 닫았다 다시 열면 "오늘 할 일 1개 남았어."만 말하고 6일 그대로다([UF-1-1](../user-flows.md) 1단계, T-BRF-1, T-BRF-2).
2. 8일 만에 열면 "오랜만이야! 다시 와서 반가워. 오늘 할 일은 1개야."이고 연속 접속 1일이다([UF-9-1](../user-flows.md) 1단계, T-BRF-4).
3. 반려동물 고르기 창에서 강아지를 고르고 바로 시작을 누르면 "처음 만났네! 나는 바둑이야. 수업부터 넣어 볼까?"이고 연속 접속 1일이다([UF-7-1](../user-flows.md), T-BRF-6).
4. 창을 켜 둔 채 04:00을 넘기면 30초 안에 출석 단추가 "출석 +20P"로 돌아오고 펫이 새 날을 브리핑하며 연속 접속이 하나 는다. 자정에는 바뀌지 않는다([UF-4-2](../user-flows.md) 2단계, T-DAYW-1, T-DAYW-2, E-DAYW-2).
5. 화면 머리 오른쪽 카드의 "출석 +20P"를 누르면 20P를 받고 단추가 "출석 완료"로 흐려지며 펫이 "출석했어! +20P"라 한다([UF-1-1](../user-flows.md) 5단계, T-ATT-1).
6. 저장할 수 없을 때 앱을 열면 "저장하지 못했어요" 창에 "연속 접속 저장에 실패해서 바꾸기 전으로 돌렸어요."가 보이고, 연속 접속은 그대로지만 브리핑은 보인다(UC-01 4a). 출석이면 "출석 저장에 실패해서 바꾸기 전으로 돌렸어요."이고 포인트, 단추, 말풍선이 누르기 전으로 돌아간다(UC-02 3a).

## 2. 입력의 경계와 프로토타입 결과

프로토타입 결과는 `prototype/src`를 컴파일한 클래스로 `AppController.windowShown`, `RewardController.attend`, `Main.create`가 만든 앱(창 없이, `java.awt.headless=true`)의 `DayWatcher.tick`과 출석 단추를 부르는 버리는 Java 파일에서 얻었다(develop `9eaadc4`, 프로토타입의 마지막 변경 `2ac06b6`, JDK 21.0.11). 프로토타입에는 저장이 없어 저장 실패 줄의 프로토타입 결과는 "없음"이다. 따로 적지 않으면 지금은 11-16(월) 10:00, 펫은 고양이 "나비" 하나, 일정은 시각 없는 할 일이다.
