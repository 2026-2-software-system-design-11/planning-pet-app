# 단위 M11. 화면이 쓰는 일정 계산

[본 구현으로 옮기기](../porting.md) 1절 표의 단위 M11이다. 07의 `DefaultDates`, `TimetableLayout`, `CalendarCell`을 `planningpet.schedule.model`에 둔다. 기준은 06 14번, 19번, 26번과 그 검사 줄, 프로토타입 `schedule/model`의 `DefaultDates`, `Planner.top`, `Planner.columns`, `TaskBook.cellPreview`다.

PR 하나의 크기 한도(1절) 때문에 셋으로 나눠 옮긴다. 일정 입력 창과 시각 고치기 창의 기본값(06 14번 `DefaultDates`)은 #371, 시간표의 열 나누기와 처음 보이는 자리(19번 `TimetableLayout`)는 #372, 달력 칸의 일의 수와 마감 표시(26번 `CalendarCell`)는 #373이다. 이 값을 그리는 화면은 S3 홈 목록, S4 일정 입력 창, S5 일정관리가 옮긴다.

07 안에서 정한 것과 그 까닭:

- **`forAdd`는 두 화면의 기본 날짜를 한 함수로 고른다.** 띄운 화면은 `planningpet.schedule.model`의 값 목록 `Screen`(`MAIN`, `SCHEDULE`)이다. 06 14번 입력 절의 두 값이고, 07은 연관이 없는 값 목록이라 상자 없이 타입으로만 적었다(07 읽는 법). `MAIN`이면 `shownStart`를, `SCHEDULE`이면 `selected`를 보지 않으므로 그 인자는 `null`이어도 된다. 프로토타입은 일정관리만 `DefaultDates.forSchedule(shownStart, today)`를 불렀고, 메인은 `MainScreen`이 달력에서 고른 날을 그대로 입력 창에 넘겼다.
- **이름은 07대로 바꾼다.** 프로토타입의 `start`는 `defaultStart`, `repeatEnd`는 `repeatEndFor`, `due`는 `dueFor`다. 프로토타입에 있던 `due(date)`(월요일 시작으로 부르는 줄임)는 07에 없고 한 주 시작은 설정 값이라(D-91) 옮기지 않는다.
- **시작 칸의 마지막 값 `LAST_START`(1675, 다음 날 03:55)는 프로토타입처럼 public 상수로 둔다.** 07 읽는 법이 그리지 않는 값이다. 시각 고치기 창과 일정 입력 창의 시작 칸 목록(05 시각 고치기 창 1번, 일정 입력 창 5번)이 같은 끝을 쓴다.
- **19번의 출력은 record `Slot`(`task`, `column`, `columns`)의 목록이다.** 일정, 열 번호, 그 무리의 열 수이고 07은 타입으로만 적었다. 목록의 순서는 06 19번 "하는 일"의 늘어놓는 순(시작 순, 같으면 긴 것 먼저, 같으면 `seq` 순)이다. 받은 목록의 순서는 보지 않는다(E-TT-5). 프로토타입 `Planner.columns`는 일정에서 `{열, 열 수}`로 가는 `HashMap`이라 순서가 없었다. 이름이 같은 `pet.model.Slot`과는 패키지가 다르다(07 "이름이 같은 `Slot` 둘").
- **`top`은 프로토타입 `Planner.top`과 같다.** 앱 날짜는 M1의 `AppDay.of`로 구한다. 지금이 앱 날짜와 같은 달력 날짜면 지금의 시각이 240(04:00)보다 작을 수 없어, 0보다 작으면 0으로 하는 06의 줄은 닿는 길이 없다. 06대로 그 줄을 둔다.
- **26번의 출력은 record `CellPreview`(`count`, `open`, `due`)다.** 셀 일의 수, 끝내지 않은 일이 있는지, 그날이 마감인 끝내지 않은 기간 할 일의 제목들(`seq` 순)이고 07은 타입으로만 적었다. 칸 글 "{수}개"(셀 일이 없으면 빈 글, D-94)는 `text()`, 셀 일도 마감 제목도 없는지는 `isEmpty()`가 준다. 프로토타입 `TaskBook.cellPreview`는 비어 있으면 `null`을 돌려줬다. 본 구현은 `null` 대신 수 0, 끝내지 않은 일 없음, 빈 제목 목록인 값을 돌려준다. 칸마다 `null`을 묻지 않고 `DailyProgress.isEmpty()`와 같은 꼴로 읽게 하려는 것이고, 비어 있는 날은 프로토타입과 같다.
- **`CalendarCell`은 앱의 오늘을 `TaskBook.today()`로 읽는다.** 끝내지 않은 일인지 가릴 때 지난 반복 사본과 지난 날의 고정 일정을 빼려면 오늘이 필요하다(D-69). 07의 `preview(book, date, withFixed)`에는 오늘 인자가 없고, `TaskBook`은 07대로 앱의 오늘을 주는 `today` 필드를 갖는다. 그 값을 읽기만 하는 메서드라 07 읽는 법이 그리지 않는다. 버린 안: `preview`에 오늘 인자를 더하기. 07의 시그니처가 바뀐다.
- **그날의 "오늘 할 일"은 `CalendarCell` 안에서 센다.** 06 6번 `dayPlan`의 `dueToday`, `timed`, `untimed`다. `DailyProgress`, `PetTalk`와 같은 꼴이다. 프로토타입은 `TaskBook.checkables`였고 07은 `TaskBook`에 이 메서드를 그리지 않았다.

## 2. 입력의 경계와 프로토타입 결과

프로토타입 결과는 `prototype/src`를 컴파일한 클래스로 `DefaultDates.forSchedule`, `start`, `repeatEnd`, `due`를 부르는 버리는 Java 파일에서 얻었다(develop `aeca409`, 프로토타입의 마지막 변경 `2ac06b6`, JDK 21.0.11). 메인의 기본 날짜는 프로토타입 코드(`MainScreen`이 `calendar.selected()`를 `TaskController.add`에 넘기고 입력 창이 그 날을 채운다)에서 읽었다. 시각은 `defaultStart`의 둘째 인자(지금)이고, 결과는 앱 하루의 분(D-77)과 그 시각이다. "본 구현" 칸의 결과는 `DefaultDatesTest`가 번호 이름의 테스트로 확인한다.

#372의 표는 프로토타입 `Planner.columns`, `Planner.top`을 부르는 버리는 Java 파일에서 얻었다(develop `a660177`, 프로토타입의 마지막 변경 `2ac06b6`, JDK 21.0.11). 일정은 모두 11-16의 할 일이다. "본 구현" 칸의 결과는 `TimetableLayoutTest`가 확인한다.

#373의 표는 프로토타입 `TaskBook.cellPreview`를 부르는 버리는 Java 파일에서 얻었다(develop `b9b1043`, 프로토타입의 마지막 변경 `2ac06b6`, JDK 21.0.11). 시계는 오늘 10:00이고, 따로 적지 않으면 일정은 할 일, 30분, 시각 없음, 끝내지 않음이다. 결과의 "비어 있음"은 프로토타입이 `null`을 준 것이다. "본 구현" 칸의 결과는 `CalendarCellTest`가 확인한다.

- E-DEF-15, 16: 마감은 그 날짜가 든 주의 마지막 날이고, 첫날이면 같은 주의 마지막 날이다. 마지막 날이면 다음 주의 마지막 날이다(D-65, D-73, D-91).
