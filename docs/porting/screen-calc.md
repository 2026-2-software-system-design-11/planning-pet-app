# 단위 M11. 화면이 쓰는 일정 계산

[본 구현으로 옮기기](../porting.md) 1절 표의 단위 M11이다. 07의 `DefaultDates`, `TimetableLayout`, `CalendarCell`을 `planningpet.schedule.model`에 둔다. 기준은 06 14번, 19번, 26번과 그 검사 줄, 프로토타입 `schedule/model`의 `DefaultDates`, `Planner.top`, `Planner.columns`, `TaskBook.cellPreview`다.

PR 하나의 크기 한도(1절) 때문에 셋으로 나눠 옮긴다. 일정 입력 창과 시각 고치기 창의 기본값(06 14번 `DefaultDates`)은 #371, 시간표의 열 나누기와 처음 보이는 자리(19번 `TimetableLayout`)는 #372, 달력 칸의 일의 수와 마감 표시(26번 `CalendarCell`)는 #373이다. 이 값을 그리는 화면은 S3 홈 목록, S4 일정 입력 창, S5 일정관리가 옮긴다.

07 안에서 정한 것과 그 까닭:

- **`forAdd`는 두 화면의 기본 날짜를 한 함수로 고른다.** 띄운 화면은 `planningpet.schedule.model`의 값 목록 `Screen`(`MAIN`, `SCHEDULE`)이다. 06 14번 입력 절의 두 값이고, 07은 연관이 없는 값 목록이라 상자 없이 타입으로만 적었다(07 읽는 법). `MAIN`이면 `shownStart`를, `SCHEDULE`이면 `selected`를 보지 않으므로 그 인자는 `null`이어도 된다. 프로토타입은 일정관리만 `DefaultDates.forSchedule(shownStart, today)`를 불렀고, 메인은 `MainScreen`이 달력에서 고른 날을 그대로 입력 창에 넘겼다.
- **이름은 07대로 바꾼다.** 프로토타입의 `start`는 `defaultStart`, `repeatEnd`는 `repeatEndFor`, `due`는 `dueFor`다. 프로토타입에 있던 `due(date)`(월요일 시작으로 부르는 줄임)는 07에 없고 한 주 시작은 설정 값이라(D-91) 옮기지 않는다.
- **시작 칸의 마지막 값 `LAST_START`(1675, 다음 날 03:55)는 프로토타입처럼 public 상수로 둔다.** 07 읽는 법이 그리지 않는 값이다. 시각 고치기 창과 일정 입력 창의 시작 칸 목록(05 시각 고치기 창 1번, 일정 입력 창 5번)이 같은 끝을 쓴다.

## 1. 화면에서 따라 할 단계

이 단위는 화면이 없다. 기본값이 화면에 드러나는 곳은 아래이고, 화면은 S3, S4, S5가 옮긴다.

1. 2026-11-14(토) 15:23에 홈 달력 18을 누르고 목록 제목 줄의 "일정 추가"를 누르면 입력 창 날짜가 2026-11-18이고 시작 시각 칸 처음 값이 09:00이다([UF-1-1](../user-flows.md) 9단계, T-DEF-1, T-DEF-8).
2. 일정관리에서 "일정 추가"를 누르면 입력 창 날짜가 오늘 2026-11-16이고, 다음 주(>)로 옮겨 누르면 2026-11-23, 이전 주(<)를 두 번 눌러 누르면 2026-11-09다([UF-2-5](../user-flows.md) 1, 2, 4단계, T-DEF-2~4).
3. 2026-11-16(월) 20:10에 메인 목록에서 C사 서류 결과 확인의 "시각 정하기"를 누르면 시각 고치기 창의 시작이 20:10이고, 달력 17을 눌러 다른 날 일의 "시각 정하기"를 누르면 09:00이다([UF-2-4](../user-flows.md) 1, 4단계, T-DEF-6, T-DEF-8). 2026-11-23(월) 08:00이면 오늘 일도 09:00이다([UF-8-2](../user-flows.md) 2단계, T-DEF-7).
4. 2026-11-20(금) 23:55에 "시각 정하기"를 누르면 시작이 23:55이고([UF-8-1](../user-flows.md) 3단계), 2026-11-21 01:30(앱 날짜 11-20)에 홈의 "일정 추가"에서 시작 시각 정하기를 켜면 날짜는 2026-11-20, 시작은 "01:30(다음 날)"이다([UF-8-1](../user-flows.md) 6단계, T-DEF-14).
5. 일정관리에서 "일정 추가"를 누르면 반복 "안 함" 아래 흐린 끝 날짜가 2026-12-14(할 일은 날짜에 4주)이고, 종류를 고정 일정으로 바꾸면 2027-03-01(15주)이다([UF-3-1](../user-flows.md) 1, 2단계, T-DEF-10, T-DEF-5).
6. 2026-11-16에 입력 창에서 기간 안에 하기를 켜면 "마감일" 칸이 2026-11-22(그 주의 일요일)이다. 설정 "한 주 시작"이 일요일이면 2026-11-21(토요일)이다([UF-2-6](../user-flows.md) 2단계, T-DEF-11, T-DEF-15).

## 2. 입력의 경계와 프로토타입 결과

프로토타입 결과는 `prototype/src`를 컴파일한 클래스로 `DefaultDates.forSchedule`, `start`, `repeatEnd`, `due`를 부르는 버리는 Java 파일에서 얻었다(develop `aeca409`, 프로토타입의 마지막 변경 `2ac06b6`, JDK 21.0.11). 메인의 기본 날짜는 프로토타입 코드(`MainScreen`이 `calendar.selected()`를 `TaskController.add`에 넘기고 입력 창이 그 날을 채운다)에서 읽었다. 시각은 `defaultStart`의 둘째 인자(지금)이고, 결과는 앱 하루의 분(D-77)과 그 시각이다. "본 구현" 칸의 결과는 `DefaultDatesTest`가 번호 이름의 테스트로 확인한다.

경계마다 본 것:

- E-DEF-1~3: 보이는 주는 `shownStart`부터 7일이고(D-91) 한 주 시작 요일은 보지 않는다. 일정관리가 넘기는 `shownStart`가 이미 그 주의 첫날이다.
- E-DEF-4: 메인은 고른 날을 그대로 준다. 지난 날을 막는 일은 저장 검사(06 2번)가 한다.
- E-DEF-5, 6: 지금을 5분 단위로 올린다. 초가 0보다 크면 그 분을 지난 것으로 보고 올린다. 그래서 15:25:30은 15:30이다.
- E-DEF-8, 9: 지금의 달력 날짜와 같은 날에서 올린 시각이 자정을 넘으면 다음 날 시각(1440)이고, 앱의 오늘인데 지금이 다음 날 새벽이면 `nextDay` 시각이다(D-77). 11-21 00:00에 11-21을 넣으면 지금의 달력 날짜와 같아 00:00과 09:00 가운데 늦은 09:00이다. 그때 앱의 오늘은 11-20이다.
- E-DEF-10, 11: 다음 날 03:55가 시작 칸의 끝이다(D-77). 04:00이 되면 앱 날짜가 바뀌어 앞날은 지난 날이고 09:00이다.
- E-DEF-12: 앱의 오늘보다 앞선 날은 늘 09:00이다. 11-16 01:00의 앱 날짜는 11-15라 11-14는 다음 날 새벽 규칙에 들지 않는다.
- E-DEF-14: 반복 끝은 주 수만 더한다. 2월 28일에 15주는 6월 13일이다(D-17, D-64).
- E-DEF-15, 16: 마감은 그 날짜가 든 주의 마지막 날이고, 첫날이면 같은 주의 마지막 날이다. 마지막 날이면 다음 주의 마지막 날이다(D-65, D-73, D-91).
