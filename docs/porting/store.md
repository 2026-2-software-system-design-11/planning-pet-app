# 단위 M8. 저장

[본 구현으로 옮기기](../porting.md) 1절 표의 단위 M8이다. 07의 `DataStore`, `SqliteDataStore`, `Schema`, `AppController.change`, `AppData.copy`, `restore`를 옮긴다. 기준은 06 21번, 22번과 그 검사 줄, 07 저장 형식, D-08, D-111이다. 프로토타입은 저장이 없어 비교 기준이 없고 06 검사 줄만 기준이다(porting.md 2절 6번).

PR 하나의 크기 한도(1절) 때문에 셋으로 나눠 옮긴다. 저장의 틀(`DataStore`, `LoadResult`, `AppData.copy`, `restore`, `TaskBook`의 지운 보상 기록 생성자, `AppController.change`)은 #351, sqlite 파일 저장과 읽기(`Schema`, `SqliteDataStore`)는 #352, 형식 번호와 강제 종료(07의 형식 번호와 변환, T-STORE-3, 4, 6, 7)는 #353이다. 시작할 때 읽고 `UNREADABLE`이면 창을 띄우는 `Main` 잇기는 창이 필요해 S1 창 틀 단위가 한다.

07 안에서 정한 것과 그 까닭:

- **되돌려도 일정과 펫은 같은 객체다.** `restore`는 사본의 값을 지금 있는 같은 `id`의 일정, 같은 종류의 펫 객체에 넣는다. 변경으로 생긴 일정과 펫은 빠지고, 변경이 지운 일정은 그 객체가 목록에 돌아온다. 일정 입력 창은 저장에 실패하면 열린 채 남고(06 22번, T-SAVE-3) 다시 저장할 때 잡아 둔 `Task`를 넘긴다. 사본 객체로 바꿔 넣으면 창이 잡은 일정이 목록 밖에 남아 다시 저장해도 바뀌지 않는다. 일정의 값을 넣는 `Task.copy`, `setFrom`은 `TaskBook`만 부르도록 package-private이다(D-109).
- **`copy`는 새 `AppData`에 `restore`한 것이다.** 같은 시계를 쓰고, 데이터 변경 알림을 받는 곳은 옮기지 않는다. 사본은 값을 담아 두기만 한다.
- **지운 보상 기록은 `TaskBook` 생성자 인자로 넣는다.** 07이 M8에 맡긴 길이다(07 "06에 없는 메서드"). 저장의 읽기가 `task` 표의 `deleted` 열로 나눈 일정을 `AppData` 생성자로 넘기고 `AppData`가 `TaskBook`에 넘긴다. 바꾸는 메서드보다 길이 좁다. 읽은 기록의 순서는 넣은 순(`seq`)이다. 표에 지운 순서 열이 없다(07 저장 형식).
- **읽기에 쓰는 값 넣는 메서드.** 06 데이터 절의 값마다 `AppData`와 `PetState`에 값 하나를 넣는 메서드를 둔다(07 읽는 법이 그리지 않는 메서드). 저장의 읽기(#352)가 쓰고, 이 단위의 검사가 모든 값을 채운 데이터를 만든다. 보상, 상점 같은 규칙은 그 규칙을 옮기는 단위가 이 메서드를 부르는 규칙 메서드로 더한다.
- **`LoadResult`는 상태, 읽은 데이터, 이유를 담는 record다.** 상태는 `LOADED`, `FIRST_RUN`, `UNREADABLE`, 이유는 값 목록(`NEWER_VERSION` 새 버전에서 만든 파일, `NOT_DATA_FILE` 플래닝펫 데이터 파일이 아님, `UPGRADE_FAILED` 옮기기 실패, `READ_ERROR` 읽기 오류)이다. 06은 "이유와 함께"라고만 적었고 05는 새 버전의 글만 정했다. 화면 글은 그 창을 옮기는 S1이 05와 함께 정한다.
- **`change`의 `errors`는 창 내용만 받는다.** "{what} 저장에 실패해서 바꾸기 전으로 돌렸어요."를 넘기고 창 제목 "저장하지 못했어요"는 창을 띄우는 view가 붙인다(07 "controller는 창을 모른다").
- **`edit`가 예외를 던지면 되돌리고 다시 던진다.** 06에 없는 길이다. 복사본으로 되돌리고, 저장하지 않고, 데이터 변경 알림을 한 번 보낸 뒤 같은 예외를 던진다. 되돌리지 않으면 반쯤 바뀐 값이 남아 틀린 값이 저장된다.

## 1. 화면에서 따라 할 단계

이 단위는 화면이 없다. 저장과 되돌리기가 화면에 드러나는 곳은 아래이고, 화면은 S1~S10 단위가 옮긴다.

1. 메인에서 할 일 체크박스를 누르면 보유 포인트, 펫 카드의 "오늘 끝낸 일" 막대, 레벨 막대가 함께 바뀐다. 앱을 끄고 다시 켜면 그대로다(06 22번 T-SAVE-5, 21번).
2. 저장할 수 없을 때(디스크가 찼을 때) 할 일 체크박스를 누르면 "저장하지 못했어요" 창에 "할 일 완료 저장에 실패해서 바꾸기 전으로 돌렸어요."가 보이고 체크와 포인트가 누르기 전으로 돌아간다(05 메인 입력 항목 4, T-SAVE-1).
3. 같은 때 일정 입력 창에서 "저장"을 누르면 창이 닫히지 않고 입력값이 남은 채 저장 실패 창이 뜬다. 디스크를 비우고 다시 "저장"을 누르면 저장된다(05 일정 입력 창 입력 항목 9, T-SAVE-3).
4. 나의 방에서 쿠션을 사다가 저장에 실패하면 포인트, 보유 목록, 놓인 아이템이 되돌아간다(05 나의 방 입력 항목 12, T-SAVE-2).
5. 빈 폴더로 앱을 열면 반려동물 고르기 창이 뜬다(UC-01 2a, T-STORE-2). 읽을 수 없는 파일이면 파일 위치와 원인을 알리는 창을 띄우고 파일을 건드리지 않고 끝낸다(UC-01 2b, 05 "데이터 파일을 못 읽음").

## 2. 입력의 경계와 결과

프로토타입 결과는 모두 "없음"이다(저장이 없다). 06에 검사 줄이 없는 되돌리기와 `change`의 경계는 `E-APP`(M7에 이어서), `E-SAVE` 번호다. "모든 값을 채운 데이터"는 06 데이터 절의 값마다 처음 값과 다른 값을 넣은 앱 데이터다. 일정은 끝내고 보상을 받은 기간 할 일, 반복 사본, 다음 날 새벽 시각의 고정 일정이 있고, 지운 보상 기록 하나, 장신구 둘을 입은 펫 둘이 있다. "본 구현" 칸의 결과는 `AppDataCopyTest`, `AppControllerTest`가 번호 이름의 테스트로 확인한다.

| 번호 | 입력과 경계 | 넣은 값 | 프로토타입 결과 | 본 구현 |
|---|---|---|---|---|
| E-APP-16 | 사본 | 모든 값을 채운 데이터의 `copy` | 없음 | 모든 값이 같다 |
| E-APP-17 | 사본은 따로다 | `copy` 뒤 원래 데이터의 일정 제목, 펫 경험치, 포인트, 출석한 날, 산 아이템을 바꾼다 | 없음 | 사본 그대로 |
| E-APP-18 | 되돌리기 | 모든 값을 채운 데이터를 `copy`한 뒤 모든 값을 바꾸고 `restore` | 없음 | 모든 값이 `copy` 때와 같다 |
| E-APP-19 | 되돌려도 같은 객체 | `copy` 뒤 일정 제목과 고양이 경험치를 바꾸고 `restore` | 없음 | 바꾸기 전에 잡은 일정과 펫 객체가 목록에 있고 옛 값이다 |
| E-APP-20 | 지운 일정 | 보상을 받은 일정을 `copy` 뒤 지우고 `restore` | 없음 | 그 객체가 목록의 원래 자리에 돌아오고 지운 보상 기록은 비었다 |
| E-APP-21 | 넣은 일정과 펫 | `copy` 뒤 반복 일정을 넣고 강아지를 데려와 고른 펫으로 정하고 `restore` | 없음 | 넣은 일정이 없고 `nextSeq` 그대로, 펫은 고양이 하나, 고른 펫 고양이 |
| E-APP-22 | 알림 받는 곳 | 알림을 받는 곳이 있는 데이터의 `copy`에 `changed`, 이어서 `restore` 뒤 원래 데이터에 `changed` | 없음 | 사본에서는 0번, 원래 데이터에서는 1번 |
| E-APP-23 | 지운 보상 기록을 넣어 만들기 | 일정 둘과 지운 보상 기록 둘(`seq` 1, 3) | 없음 | 지운 보상 기록 `seq` 1, 3, 보상 기록이 지운 일 다음 남은 일 순 |
| T-SAVE-3 | 저장 실패, 일정 넣기 | 늘 실패하는 저장소. 할 일 하나를 넣는 변경 | 없음 | 일정 0개, `nextSeq` 1. 창이 열린 채 입력값이 남는 것은 S4가 확인한다 |
| E-SAVE-1 | 저장 성공 | 정상 저장소. 할 일 하나를 넣는 변경 | 없음 | 저장 1번(넣은 뒤의 값), 알림 1번, 오류 창 없음 |
| E-SAVE-2 | 저장 실패의 글 | 늘 실패하는 저장소, 이름 "할 일 완료" | 없음 | 오류 창 1번, "할 일 완료 저장에 실패해서 바꾸기 전으로 돌렸어요.", 알림 1번 |
| E-SAVE-3 | 되돌린 뒤에 알린다 | 늘 실패하는 저장소, 30P. 50P로 바꾸고 출석한 날을 더하는 변경 | 없음 | 30P, 출석한 날 없음. 알림을 받는 곳이 본 포인트도 30P |
| E-SAVE-4 | 변경이 예외를 던짐 | 정상 저장소. 할 일 하나를 넣고 예외를 던지는 변경 | 없음 | 같은 예외가 나간다. 일정 0개, 저장 0번, 알림 1번 |

06 22번의 다른 검사 줄은 그 변경을 옮기는 단위가 확인한다. T-SAVE-1과 T-SAVE-4(할 일 완료)는 M9 보상, T-SAVE-2(쿠션 사기)는 M15 상점과 방, T-SAVE-5(메인 화면의 알림 한 번)는 S3 홈 목록이다.
