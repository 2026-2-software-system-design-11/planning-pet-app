# 06. 함수 명세

유스케이스([02-usecases.md](02-usecases.md))와 결정([decisions.md](decisions.md))을 코드의 함수로 옮긴다. 형식은 개인과제 CP3 양식의 FUNCTION SPECIFICATION(시그니처, 입력, 출력, 하는 일)에 쓰는 곳, 오류, 검사 표를 더했다.

## 읽는 법

- 검사 표의 한 줄은 JUnit 테스트 하나다. 테스트 이름에 검사 번호(예: `T-DAY-1`)를 넣는다. 만든 앱이 이 표를 모두 통과하면 이 명세대로 만든 것이다.
- 지금 시각은 주입한 `java.time.Clock`에서 얻는다. 표의 시각은 운영체제 시간대의 시각이다.
- 표의 날짜는 2026년이다. 2026-11-16은 월요일이다.
- "오늘"은 앱 날짜(D-15)다. 포인트는 P, 경험치는 "경험치 N"으로 적는다.
- 패키지는 `planningpet.model`(데이터와 규칙), `planningpet.store`(저장), `planningpet.app`(화면과 Model을 잇는 Controller), `planningpet.ui`(Swing)다. 클래스 사이의 관계와 저장 파일 형식은 07에서 그린다.

## 데이터

검사 표가 가리키는 값이다. 07의 클래스 다이어그램은 이 값을 빠짐없이 담는다.

| 대상 | 값 | 뜻 |
|---|---|---|
| `Task` | `id` | 바뀌지 않는 번호(UUID 문자열) |
| | `seq` | 넣은 순. 새 일정마다 1씩 늘고 고쳐도 바뀌지 않는다 |
| | `kind` | `TASK`(할 일) 또는 `FIXED`(고정 일정, D-16) |
| | `title`, `date`, `startTime`, `durationMinutes`, `memo` | 제목, 날짜, 시작 시각(없으면 `null`), 걸리는 시간(분), 메모 |
| | `seriesId` | 매주 반복으로 만든 사본끼리 같은 번호. 반복이 아니면 `null`(D-17) |
| | `done` | 끝냈는지 |
| | `rewardPoints`, `rewardExp`, `rewardDay` | 이 할 일로 받은 포인트와 경험치, 받은 앱 날짜. 받지 않았으면 0, 0, `null` |
| `AppData` | `points`, `exp` | 보유 포인트(음수가 될 수 있다, D-19)와 누적 경험치 |
| | `rewardCountDay`, `rewardCount` | 보상을 받은 완료 횟수와 그 앱 날짜(하루 상한, D-18) |
| | `attendanceDay` | 마지막으로 출석한 앱 날짜 |
| | `lastOpenDay`, `streak` | 마지막으로 브리핑한 앱 날짜와 연속 접속 일수(D-21, D-23) |
| | `pet` | 종류(`CAT`, `DOG`)와 이름 |
| | `ownedItems`, `placedItems` | 산 아이템과 방에 놓인 아이템 |
| | `trayNoticeShown` | 처음 창 닫기 안내를 했는지(D-29) |
| | `nextSeq` | 다음 일정에 줄 `seq` |

## 1. `LocalDate AppDay.of(LocalDateTime time)`

시각이 속한 앱 날짜를 돌려준다.

- **쓰는 곳**: "오늘"이 필요한 모든 곳(UC-01, UC-02, UC-07, UC-09, UC-13)
- **입력**: 시각
- **출력**: 앱 날짜
- **하는 일**: `time.minusHours(4).toLocalDate()`(D-15)

| 검사 | 하는 것 | 결과 |
|---|---|---|
| T-DAY-1 | 11-16 03:59 | 11-15 |
| T-DAY-2 | 11-16 04:00 | 11-16 |
| T-DAY-3 | 11-16 23:59 | 11-16 |
| T-DAY-4 | 2027-01-01 03:00 | 2026-12-31 |

## 2. `List<FieldError> TaskDraft.validate()`

일정 입력 창에 쓴 값이 저장할 수 있는 값인지 본다.

- **쓰는 곳**: 일정 입력 창의 저장(UC-03, UC-05), 빠른 추가(UC-04)
- **입력**: `TaskDraft`(종류, 제목, 날짜, 시작 시각, 걸리는 시간, 메모, 반복 끝 날짜). 반복을 고르지 않았으면 반복 끝 날짜는 `null`이다.
- **출력**: 잘못된 칸과 문장의 목록. 칸 순서(제목, 시작 시각, 걸리는 시간, 메모, 반복)로 담는다. 비어 있으면 저장할 수 있다.
- **하는 일**: 제목은 앞뒤 공백을 지운 뒤 잰다. 날짜는 제한이 없다(지난 날짜도 된다). 아래 표 밖의 값은 모두 통과한다.

| 검사 | 하는 것 | 결과 |
|---|---|---|
| T-VAL-1 | 제목 "  과제  ", 할 일, 30분 | 오류 없음. 저장되는 제목은 "과제" |
| T-VAL-2 | 제목 "   " | 제목: "제목을 써 주세요" |
| T-VAL-3 | 제목 101자 | 제목: "제목은 100자까지예요". 100자는 오류 없음 |
| T-VAL-4 | 할 일, 시작 시각 없음 | 오류 없음 |
| T-VAL-5 | 고정 일정, 시작 시각 없음 | 시작 시각: "고정 일정은 시작 시각이 있어야 해요" |
| T-VAL-6 | 시작 09:05 | 시작 시각: "10분 단위로 정해 주세요" |
| T-VAL-7 | 시작 23:30, 30분 | 오류 없음(끝 24:00) |
| T-VAL-8 | 시작 23:30, 40분 | 시작 시각: "하루 안에 끝나야 해요" |
| T-VAL-9 | 걸리는 시간 0, 25, 730 | 각각 걸리는 시간: "10분부터 720분까지, 10분 단위예요". 10과 720은 오류 없음 |
| T-VAL-10 | 메모 1001자 | 메모: "메모는 1000자까지예요" |
| T-VAL-11 | 할 일에 반복 끝 날짜 | 반복: "반복은 고정 일정만 할 수 있어요" |
| T-VAL-12 | 고정 일정 11-16, 반복 끝 11-15 | 반복: "끝 날짜가 시작 날짜보다 앞이에요" |
| T-VAL-13 | 고정 일정 11-16, 반복 끝 2027-05-10(25주 뒤) | 오류 없음(26번). 2027-05-17이면 반복: "반복은 26번까지예요" |
| T-VAL-14 | 제목 "", 걸리는 시간 25 | 제목, 걸리는 시간 순서로 오류 두 개 |

## 3. `List<Task> TaskBook.add(TaskDraft draft)`

검사를 통과한 입력으로 일정을 만든다.

- **쓰는 곳**: UC-03, UC-04
- **입력**: `validate()`가 오류 없음을 돌려준 `TaskDraft`
- **출력**: 만든 일정. 반복이면 사본 전부를 날짜 순으로 돌려준다.
- **오류**: 검사를 통과하지 않은 입력이면 `IllegalArgumentException`
- **하는 일**: 새 일정은 `done` false, 보상 0이다. 반복이면 시작 날짜부터 끝 날짜까지 7일씩 더한 날마다 사본을 만들고 같은 `seriesId`를 준다(D-17). `seq`는 날짜 순으로 하나씩 준다.

| 검사 | 처음 상태 | 하는 것 | 결과 |
|---|---|---|---|
| T-ADD-1 | 일정 없음, `nextSeq` 1 | 할 일 "과제" 11-16 추가 | 일정 1개, `seq` 1, `done` false, 보상 0, `seriesId` null. `nextSeq` 2 |
| T-ADD-2 | T-ADD-1 뒤 | 할 일 하나 더 추가 | 새 일정의 `seq` 2 |
| T-ADD-3 | 일정 없음 | 고정 일정 11-16(월) 10:30, 75분, 반복 끝 12-28 | 7개(11-16, 11-23, 11-30, 12-07, 12-14, 12-21, 12-28). 모두 같은 `seriesId`, `seq` 1~7 |
| T-ADD-4 | 일정 없음 | T-ADD-3과 같고 반복 끝 12-30(수) | T-ADD-3과 같은 7개 |

## 4. `void TaskBook.update(Task task, TaskDraft draft)`

이미 있는 일정을 고친다.

- **쓰는 곳**: UC-05
- **입력**: 고칠 일정, 검사를 통과한 새 값. 수정 창에는 종류와 반복 칸이 비활성이라 바뀌지 않는다.
- **오류**: 종류가 다르면 `IllegalArgumentException`
- **하는 일**: 제목, 날짜, 시작 시각, 걸리는 시간, 메모만 바꾼다. `id`, `seq`, `seriesId`, `done`, 보상은 그대로 둔다(D-18). 반복 사본은 고친 하나만 바뀐다.

| 검사 | 처음 상태 | 하는 것 | 결과 |
|---|---|---|---|
| T-EDIT-1 | 끝낸 할 일, 보상 10P와 경험치 10, `rewardDay` 11-16 | 날짜를 11-20, 걸리는 시간을 120분으로 | 날짜와 시간만 바뀐다. `done`, 보상, `rewardDay`, 보유 포인트 그대로 |
| T-EDIT-2 | T-ADD-3의 사본 7개 | 11-30 사본의 시작을 13:00으로 | 그 하나만 13:00. `seriesId` 그대로 |
| T-EDIT-3 | `seq` 3인 할 일 | 제목을 고침 | `seq` 3 그대로 |

## 5. `void TaskBook.delete(Task task, DeleteScope scope)`

일정을 지운다.

- **쓰는 곳**: UC-06
- **입력**: 지울 일정, 범위(`ONLY_THIS` 또는 `THIS_AND_AFTER`). 반복 사본이 아니면 화면은 범위를 묻지 않고 `ONLY_THIS`를 넘긴다.
- **하는 일**: `THIS_AND_AFTER`는 같은 `seriesId`에서 날짜가 같거나 뒤인 사본을 모두 지운다. 끝낸 할 일을 지워도 보유 포인트, 경험치, 오늘 상한 횟수는 그대로다(D-19).

| 검사 | 처음 상태 | 하는 것 | 결과 |
|---|---|---|---|
| T-DEL-1 | 오늘 끝내 10P를 받은 할 일, 보유 30P, 오늘 횟수 1 | 지움 | 일정이 없어진다. 30P, 경험치, 횟수 1 그대로 |
| T-DEL-2 | T-ADD-3의 사본 7개 | 12-07 사본을 `ONLY_THIS` | 6개 남음 |
| T-DEL-3 | T-ADD-3의 사본 7개 | 12-07 사본을 `THIS_AND_AFTER` | 11-16, 11-23, 11-30만 남음 |

## 6. `List<Task> TaskBook.forDate(LocalDate date)`

메인 할 일 목록에 보일 일정을 순서대로 돌려준다.

- **쓰는 곳**: UC-01, UC-09 (메인 할 일 목록)
- **입력**: 고른 날짜
- **출력**: 그 날짜의 할 일(`TASK`). 고정 일정은 넣지 않는다(D-16). 시작 시각이 있는 것을 시각 순으로 먼저, 없는 것을 그 아래에 둔다. 시각이 같거나 둘 다 없으면 `seq` 순이다. 끝낸 할 일도 제자리에 있다.

| 검사 | 처음 상태 | 하는 것 | 결과 |
|---|---|---|---|
| T-LIST-1 | 11-16에 A(15:00, seq 3), B(시각 없음, seq 1), C(09:00, seq 4), D(15:00, seq 2), E(고정 10:30), F(시각 없음, seq 5, 끝냄) | `forDate(11-16)` | C, D, A, B, F |

## 7. `List<Task> TaskBook.untimedOfWeek(LocalDate monday)`

일정관리 오른쪽 목록에 보일 시각 없는 할 일을 돌려준다.

- **쓰는 곳**: UC-10, UC-11
- **입력**: 보이는 주의 월요일
- **출력**: 월요일부터 일요일까지 날짜의 시각 없는 할 일. 끝낸 것도 넣는다. 날짜 순, 같은 날은 `seq` 순이다.

| 검사 | 처음 상태 | 하는 것 | 결과 |
|---|---|---|---|
| T-WEEK-1 | 시각 없는 할 일 11-15, 11-16(끝냄), 11-22, 11-23. 11-18에 시각 있는 할 일 | `untimedOfWeek(11-16)` | 11-16, 11-22 |
